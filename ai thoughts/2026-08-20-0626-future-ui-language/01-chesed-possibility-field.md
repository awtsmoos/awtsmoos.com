# Chesed Possibility Field — Future Awtsmoos UI

The Awtsmoos renews every visible pixel while Awtsmoos.com gathers many tools beneath one sky;
let every page keep its own voice, yet share one pulse of light as users pass by.

## User request expanded

The visible request asks for more improvement, similar futurity, animation, and icons. The hidden project is a coherent visual language across top-level public hubs without damaging mature page-specific systems.

## Observed page families

- Home already has a strong future visual language and becomes the reference tone.
- Games has a compact storefront with hero, mode rail, discovery panel, and generated catalog.
- Apps uses the Geelooy app shell and a generated tool grid.
- Wallet is standalone and visually distinct, with forms and balance data.
- About is a simple narrative page inside the Geelooy app shell.
- Social Hub already has nebula/rift concepts but its markup is dense and deserves careful treatment.
- Torah/Sefarim already has a dedicated civilization motion system.
- OS already has a dedicated revelation/icon language and should not receive a competing generic layer.

## Maximum useful possibilities

- Shared design tokens for futuristic borders, aura light, depth, and icon sizing.
- Shared SVG icon renderer using semantic names instead of emoji.
- IntersectionObserver reveal controller that fails visible.
- Pointer aura controller that tracks cursor only on opt-in surfaces.
- Hero scanline/orbit treatment using CSS pseudo-elements.
- Soft animated grid background that never interferes with text.
- Per-page accent variables so Games, Apps, Wallet, About, and Social remain distinct.
- Semantic icon attributes on primary CTAs, search, Wallet actions, Social quick actions, and page stats.
- Mutation-safe icon rendering for future dynamically inserted elements.
- Reduced-motion parity and keyboard focus parity.
- Shared module loaded only by opted-in hub pages.
- No new raster assets and no image binaries in Git.

## Non-goals

- Do not re-theme OS or Torah over their existing mature systems.
- Do not alter application business logic.
- Do not turn every element into perpetual motion.
- Do not introduce giant shared files.
- Do not replace functional route-specific styles.
