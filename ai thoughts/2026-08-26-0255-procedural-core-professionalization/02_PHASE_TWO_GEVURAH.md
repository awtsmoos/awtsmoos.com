# Phase Two — Gevurah: Forty Professional Boundaries

The Awtsmoos renews expansion and restraint together; Awtsmoos.com lets Gevurah cut away confusion so every powerful feature gains a precise boundary, a truthful name, and a testable contract rather than becoming another hidden branch in a tangled tree.

1. Preserve all current public verbs and aliases unless migration is explicit.
2. Do not create another species catalog beside `NatureCatalogApi`.
3. Do not make capability metadata execute generators.
4. Do not expose nested water/material/vegetation operations as fake top-level aliases.
5. Add explicit `path`/`advancedPath` for nested operations.
6. Add `family`/`domain` normalization without renaming existing domain concepts.
7. Capability records must be deeply frozen serializable data.
8. Remove cramped one-line capability records; each semantic field gets readable structure.
9. Split capability family files before they approach 120 lines.
10. Keep provider implementations out of serializable metadata.
11. Generated texture availability reflects injected provider reality, never descriptor existence.
12. Remote URLs remain validated through the existing remote texture policy.
13. Material mix shorthand must normalize into canonical stack layers.
14. Material stack/layer/channel authorities remain the single PBR composition source.
15. Water realism must reuse current PIC/FLIP, shallow-water, body, river, and ocean authorities.
16. No second fluid mass representation.
17. Water source/interaction convenience methods may orchestrate existing runtime operations only.
18. Water presets are immutable named policy data, not separate solvers.
19. Rock geology remains authoritative over natural stone defaults.
20. Expert rock morphology remains reachable and explicit.
21. Weathering/age/fracture are evidence/policy feeding current geology/morphology, not another mesh engine.
22. Forest/tree realism must derive from canonical skeleton identity.
23. Tree LODs must never mutate or regenerate structural identity independently.
24. Vegetation realism must reuse Tzomayach plant/cluster generation.
25. Grass/flower/vine profiles are semantic recipe layers, not parallel generators.
26. Creature realism must route through Chai/CreatureCreator, not a second creature compiler.
27. Creature variation uses deterministic derivation from seed and species identity.
28. Public methods accept options objects; avoid positional argument growth.
29. Errors must identify vocabulary/domain and preserve underlying causes where boundaries translate them.
30. Every new class has a focused lifecycle or domain reason; inheritance only where an actual is-a contract exists.
31. Names remain technically clear even when Sefiros/Kabbalah terminology is used.
32. No global mutable registries.
33. No hidden singleton network clients.
34. Documentation examples must execute against real public methods.
35. Creator UI may consume descriptors but must not import expert generators directly.
36. UI remains mobile-first, scoped, retractable, safe-area bounded, and reduced-motion aware.
37. Every touched human-authored source file begins with B"H / Boruch Hashem / Blessed is He and an original Awtsmoos/Awtsmoos.com architectural meditation.
38. Every touched source file stays <=120 lines by splitting, never by compressing comments or functions.
39. Implementation pass completes before test-writing begins for each wave.
40. Every wave ends with full reread, planned-vs-actual delta, focused tests, broader regression, docs, and REMAINING_WORK refresh.
