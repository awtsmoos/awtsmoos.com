# Phase One — Chesed: Maximum Professionalization Field

The Awtsmoos renews every world from nothing in every instant; Awtsmoos.com can therefore reveal one procedural library whose outer API feels effortless while its inner authorities remain precise, modular, realistic, and infinitely extensible.

## Unified API ideal

- `nature.capabilities` becomes the authoritative discovery language for every direct and nested procedural operation.
- Top-level verbs remain intentionally tiny: creature, plant, flora, grass, tree, forest, rock, material, flowers, river, world.
- Rich specialist domains remain first-class: `nature.water`, `nature.vegetation`, `nature.forests`, `nature.creatures`, `nature.rocks`, `nature.materials`, `nature.ecosystems`.
- Every domain supports a consistent grammar where meaningful: create, plan, profile, presets/list, simulate/runtime, expert.
- Capability records encode public path, domain, level, result kind, execution kind, seed/quality/realism support, provider requirements, simple fields, advanced groups, aliases, and tags.
- Nested paths are discoverable without pretending every nested method is a top-level alias.
- The capability layer becomes the source for docs, creator advanced controls, validation hints, command palettes, future agents, and autocomplete.

## Realism expansion ideal

### Water
- Named regimes: calm pool, stream, river, rapids, waterfall, flood, runoff, wetland, lake, ocean, spring/wellspring, fountain, pour, splash, burst.
- Source/interaction vocabulary above the existing conserved 3D fluid runtime rather than a second solver.
- Material/optical realism, secondary effects, turbulence, foam/spray/bubbles/mist, transfer, pouring, impulses, container interactions.
- Ocean condition profiles and shallow-water condition profiles.
- Nested capability records for every current real water method.

### Rocks
- Geology profile, lithology/material, fracture, weathering, erosion, sediment, lichen/moss coverage, wetness, age, strata, talus/boulder-field planning.
- Separate geological evidence from mesh realization.
- Rock-field placement influenced by slope/hydrology/ecology without renderer coupling.

### Materials/textures
- PBR channel composition, stack/mix recipes, generated texture provider, remote URL policy, provenance, cache keys, fallback chain, reproducible generation requests.
- Professional named material recipes that can be shared by rocks, bark, soil, grass, flowers, creatures, buildings, and water.
- Generation never silently performs network work; injected provider is explicit.

### Vegetation / flowers / grass / vines
- Growth-stage/seasonal intent, motion/wind, ecological density, clumping, patch geometry, species profiles, LOD, soil/moisture/light response.
- Flower inflorescence and cluster vocabulary beyond a generic patch while still delegating canonical geometry to Tzomayach.
- Grass meadow/turf/wild/understory profiles rather than one opaque plan call.

### Trees / forests
- Age, season, root spread, canopy metrics, wind response, health/stress, deadwood, competition, succession, riparian/forest-edge response.
- All detail derived from the one canonical tree skeleton.

### Creatures
- Discoverable species/morphology/traits/material/behavior intent.
- Simple creation by species with expert creator remaining the canonical escape hatch.
- Population/variation planning through deterministic seeds rather than ad hoc randomization.

## Documentation and tooling ideal

- One `README` section: 30-second API, domain API, expert API.
- Capability examples generated from or checked against actual registry vocabulary.
- `nature.capabilities.describe()` provides enough metadata for clean progressive UI without importing generator internals.
- No stale parallel docs tables.

## UI ideal

- Creator default view stays minimal.
- Advanced drawer groups capability domains dynamically.
- Selected capability reveals only simple fields first; advanced groups remain retractable.
- No global styles, no z-index drift, no offscreen panels, full hover/active/focus-visible/disabled/selected states.
- Mobile-first and keyboard-safe.
