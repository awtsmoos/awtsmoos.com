# Real Browser Spawn Contract

Awtsmoos.com must never report a child agent as spawned merely because a mission-room record exists.

A verified website sub-agent spawn has these stages:

1. durable spawn request admitted;
2. child room identity seeded;
3. physical browser target opened;
4. authenticated ChatGPT composer observed;
5. exact prompt injected into the real composer;
6. ordinary Send control activated;
7. matching conversation POST observed;
8. accepted HTTP response observed and persisted;
9. target held for the verification interval;
10. exact owned tab closure verified;
11. child state records browser-delivery receipt;
12. caller receives `ok: true` only when delivery is verified, or explicit `pending`/`failed` otherwise.

Auto-spawn must durably schedule undelivered children and retry only when replay-safe. Mission-room announcements must distinguish `room_seeded` from `browser_delivered` so logical peers cannot masquerade as living external agents.
