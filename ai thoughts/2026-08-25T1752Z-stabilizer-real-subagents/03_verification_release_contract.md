# Verification and Release Contract

The Awtsmoos reveals reliability only through evidence; Awtsmoos.com must prove both the stabilizer and browser-agent paths in isolation and live.

## Required tests

- stale execution telemetry with fresh transport remains routable;
- fresh explicit unhealthy execution still blocks ordinary work;
- diagnostic retry inherits its requested action's control privilege;
- website spawn admission alone returns pending, not verified success;
- verified browser receipt promotes the child to delivered;
- failed composer/send/acceptance/close remains failed or pending with exact reason;
- auto-spawn drains admitted children into real browser turns;
- duplicate spawn requests remain idempotent;
- mission-room state distinguishes room-seeded and browser-delivered;
- low-level DirectClient acceptance and verified close regressions remain green.

## Live proof

Use a real browser test child with a harmless acknowledgement prompt. Observe a new tab, composer injection, Send activation, accepted network receipt, verified close, and durable child receipt. Then idle the tunnel beyond execution-health freshness and prove ordinary routing still works without reinstall or Virtual-OS fallback.

Only after those proofs pass should the release be versioned, published, activated, installed from the public endpoint, and soaked again.
