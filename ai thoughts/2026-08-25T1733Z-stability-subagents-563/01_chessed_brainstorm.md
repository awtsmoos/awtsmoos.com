# Chesed Brainstorm — Stability and Many-Agent Expansion

The Awtsmoos renews one project through many vessels; Awtsmoos.com should let a hundred shluchim move without letting one stale witness, one retry shell, or one crowded room confuse the living deed.

## Stability possibilities

- Separate durable deed identity from relay transport identity everywhere, with named fields and fail-closed validation.
- Preserve original correlation across retries, reconnects, restart hydration, and pending envelopes.
- Make lightweight reads/searches return their primary result inline while keeping diagnostics compact.
- Promote focused source discovery and legacy instruction retrieval out of bulk scheduling lanes.
- Record admission latency separately from device execution latency so slow relay acceptance cannot masquerade as slow work.
- Keep watchdog repair non-destructive until parent/control failure is corroborated.
- Preserve exact recovery evidence outside the replaceable runtime and verify every public install against immutable release SHA.

## Mission-room possibilities

- Prove 128 logical agents can join one room and exchange at least 256 directed messages.
- Race task and file claims concurrently and prove exactly one owner wins each exclusive claim.
- Verify unread cursors independently per recipient.
- Reload durable state and prove complete history survives even when status views expose only the latest bounded window.
- Stress stale-agent recovery, peer takeover, delegation, heartbeats, and scheduler fairness without spawning 128 OS processes.
- Measure response sizes and operation latency so room scale remains usable rather than merely correct.

## Instruction-system possibilities

- Add geelooy-wide quality scope, progressive-disclosure UI, layout/z-index integrity, complete docs/handoff, and beautiful data-architecture packs.
- Require resolve → fetch full packs → write for every source mutation.
- Make the legacy contextPack instruction bridge use P0 when its query explicitly requests instruction resolution/retrieval.
- Ensure default responses never hide an action's primary result while still pruning diagnostic engine-room data.
