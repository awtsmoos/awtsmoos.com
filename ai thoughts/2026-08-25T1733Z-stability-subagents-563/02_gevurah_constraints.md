# Gevurah — Constraints and Failure Boundaries

The Awtsmoos gives every expansion a vessel; Awtsmoos.com must not trade stability for ambition, nor security for convenience.

## Hard constraints

- Never weaken correlation by accepting an unrelated response merely because an action name matches.
- Keep canonical deed identity distinct from transport/retry receipt identity.
- A retry may observe or safely recover the same durable deed; it may not create a second mutation after device acceptance.
- Preserve current restart hydration, accepted-request non-redispatch, action-alias, path, job, stream, and nonce protections.
- Keep the working 1.0.562 primary untouched until the 1.0.563 candidate passes isolated tests and release gates.
- Do not merge or reset the user's dirty main checkout while unrelated concurrent work exists.
- Mission-room scale tests should use logical agents; process-level races already have focused subprocess tests and should remain bounded on this 4-core/8-GB Mac.
- Bounded room/status views must never mean bounded durable history unless explicitly documented as retention policy.
- Response focusing may remove diagnostics, never the action's primary semantic result.

## Release completion evidence

- Focused retry-correlation regression passes for differing deed/transport identities and foreign responses still fail closed.
- Existing relay restart/retry tests remain green.
- 128-agent room contract passes ownership, messaging, cursor, persistence, and bounded-view invariants.
- Watchdog corroboration and 100-agent capacity regressions remain green.
- Public release activation is independently verified, then the Mac installs that public SHA and remains healthy through a soak.
