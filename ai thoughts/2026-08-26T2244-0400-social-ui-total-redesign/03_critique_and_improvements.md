# Tiferes Critique — Thirty Improvements Before Code

Boruch Hashem. Blessed is He.

Tiferes joins breadth with discipline: the Awtsmoos.com social vessel should feel inevitable, simple, and alive. These improvements challenge the first instinct before any source is rewritten.

1. Do not begin with colors; begin with task hierarchy.
2. Do not keep three visible columns at 430px.
3. Give the editor one dominant content surface.
4. Collapse preview by default on narrow widths.
5. Collapse posting identity into a compact editable summary.
6. Collapse destinations into a compact editable summary.
7. Show advanced metadata only when requested.
8. Replace repeated border boxes with whitespace and dividers.
9. Reduce the number of simultaneously visible actions.
10. Move destructive draft clearing out of the primary action row.
11. Use one primary action color consistently.
12. Reserve danger color for confirmations/errors, not standing UI.
13. Remove decorative neon outlines where they do not signal focus or selection.
14. Remove uppercase micro-labels that duplicate headings.
15. Use a coherent type scale instead of giant serif headline plus tiny utility text.
16. Keep page title proportional on mobile.
17. Prefer short control labels with clear grouping.
18. Use segmented controls only for genuinely mutually exclusive choices.
19. Distinguish creation modes from authoring tools.
20. Prevent toolbar wrapping into visually chaotic rows.
21. Use horizontal scrolling for optional tool strips only if discoverable and keyboard-safe.
22. Prefer disclosure panels to dense permanent tool matrices.
23. Keep sticky primary actions clear of iOS/macOS safe-area concerns.
24. Verify long titles, filenames, URLs, and errors do not force overflow.
25. Verify preview close/open does not cause layout jumps that obscure the editor.
26. Make empty states useful instead of merely blank.
27. Ensure selected state is stronger than hover state.
28. Ensure hover is nonessential on touch devices.
29. Audit any global social styles for leakage into unrelated apps.
30. Build reusable social surface/button/section primitives only where the real code graph proves repetition.
31. Preserve server/draft/publication semantics while changing presentation.
32. Keep animation subtle and state-driven.
33. Test live at the screenshot's exact simulated width.
34. Compare before/after DOM density and visible action count, not aesthetics alone.
35. Extend the redesign to adjacent social pages only after shared causes are proven.
