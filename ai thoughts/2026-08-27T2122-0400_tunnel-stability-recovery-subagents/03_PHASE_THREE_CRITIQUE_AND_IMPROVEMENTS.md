# Phase Three — Critique and Improvements

## Thirty plan improvements
1. Separate transport failure from execution failure.
2. Separate stale telemetry from explicit unhealthy telemetry.
3. Require current-generation evidence for destructive repair.
4. Require exact PID birth/generation identity where available.
5. Cancel repair on fresh execution success.
6. Cancel repair on active runtime pressure.
7. Cancel repair when stall evidence disappears.
8. Persist repair claims before signals.
9. Bound repair frequency durably.
10. Export mailbox evidence before cleanup.
11. Reconcile terminal result before quarantine.
12. Never redispatch accepted ambiguous mutations.
13. Reclaim only proven stale non-execution.
14. Release accounting when custody is safely retired.
15. Put mailbox diagnostics on control capacity independent of user work.
16. Record queue phase transitions, not just counts.
17. Track requester ownership for fairness.
18. Reclaim expired reservations deterministically.
19. Keep completed job output observation outside execution admission.
20. Benchmark commandStart receipt latency separately.
21. Preserve original deed identity through retryAction.
22. Treat transport receipt identity as separate metadata.
23. Let verified late completion supersede timeout operationally, retaining timeout history.
24. Dedupe browser missions from normalized deterministic intent.
25. Require physical Send and accepted `/conversation` proof.
26. Require verified tab close before browser mission success.
27. Make directed mission messages durable and idempotent.
28. Make docs queryable by ids/tags/actions/paths/failure modes.
29. Verify generated manifest and deployed artifact against exact main SHA.
30. Delete branches/worktrees only after proving unique commits and dirty files are preserved.

## Plan risks
Concurrent agents are active on this repository and tunnel. Any source rewrite must re-read the complete file immediately before writing and must avoid overwriting unrelated dirty work. Large files may require modular split rather than contraction. Release is forbidden until tests and live proofs close the verification graph.
