# Post-Archaeology — What Reality Changed

The Awtsmoos reveals a deeper vessel whenever old assumptions fall away;
Awtsmoos.com improves by reading the living source, not by forcing yesterday's map onto today.

## What the first plans assumed

The first all-page plans expected that generic focus, layer, motion, responsive, and state foundations might still be missing, and that the old tunnel circuit implementation might require a direct rewrite.

## What current source proved

1. `geelooy/css/geelooy-surface/` already provides a strong, opt-in, root-scoped foundation for box sizing, overflow, touch size, focus-visible, hover, active, disabled, semantic layers, safe areas, drawers, modals, reduced motion, and bounded animation.
2. `geelooy/style/geelooy-app/` already composes rich route-shell controls, native fields, disclosures, status controls, editors, empty/loading states, skip links, responsive/accessibility modules, and performance containment.
3. Therefore the all-page UI problem is primarily **adoption, SSR/resilience, route-family integration, legacy utility modernization, and production correctness**, not absence of a design system.
4. The current `geelooy/apps/tunnel/agent/lib/runtime/circuit-breaker.js` is already redesigned to use current + p90 representative lag rather than max historical lag and to defer lag-only pressure instead of rejecting accepted work.
5. `main-pressure-queue.js` still makes lane start depend on the circuit gate, so sealed P0/control/recovery independence must be proven through the emergency/control dispatch path rather than assumed from queue limits.
6. The newly installed native release now reports source SHA `2eed3f7c0cbc537e68187d8d461adb9b09d155c8`, matching the previously observed `origin/main`, while the local working branch was five commits behind. Git reality must be refreshed before any integration.
7. Generation replacement cleared the ancient outbox debt. That is not proof that live-generation settlement is complete; it remains a regression target.
8. Dynamic Torah templates still contain a loading-only `#realPost` fallback, and one template explicitly contains `charset=ISO-8859-1`. Production deep Torah content has been observed with the wrong MIME/weak semantic body, so response/template correctness is a site-wide priority above cosmetics.
9. `StaticAssetNegotiation.js` and compact URL transform work changed upstream and locally; these must be reconciled, not overwritten.
10. Multiple sibling agents are actively changing the same repository. Global staging is forbidden until their writes settle and all work is preserved.

## Revised implementation order

### A. Stability closure without duplicate rewrites

Read complete current source/diff/origin for:
- `geelooy/apps/tunnel/agent/lib/runtime/circuit-policy.js`
- `geelooy/apps/tunnel/agent/lib/runtime/circuit-liveness.js`
- `geelooy/apps/tunnel/agent/lib/runtime/main-queue-emergency.js`
- the mailbox emergency registry/dispatcher and parent recovery preflight modules.

Only write if a real gap remains. Required proof: P0 status/observe/mailbox recovery progresses under artificial P3/P4 pressure; live stale terminal debt reconciles without generation replacement; fresh progress blocks destructive recovery.

### B. Server correctness first

Read complete current, local diff, and origin versions of:
- `ayzarim/awtsmoosDynamicServer/fileServer.js`
- `ayzarim/awtsmoosDynamicServer/static/HtmlUiFoundation.js`
- `ayzarim/awtsmoosDynamicServer/static/StaticAssetNegotiation.js`
- new upstream `StaticAssetEncodingQuality.js` and `StaticAssetFreshness.js`
- the Heichel/post route/template render path.

Repair only proven gaps in MIME, UTF-8, fallback HTML, cache/encoding negotiation, and compact variation.

### C. Route-family adoption

Use the existing shared surface contract rather than inventing a second global design system. Add small adapters only where route families do not opt in cleanly.

Prioritize:
1. Torah post/Heichel SSR and reading shell.
2. Social Hub signed-out/read-only fallback.
3. Apps Docs semantic fallback.
4. Legacy utility shell for Audio Editor / CSV / similar tools.
5. Register/Login/Wallet state consistency.
6. Games launch/loading shells and performance deferral.
7. OS/Code creator-tool responsive command surfaces.

### D. Compact/load correctness

Read canonical compact response/compiler path and reconcile upstream changes before editing. `?compact=true` must preserve semantics and query/hash/module resolution. Measure normal vs compact bytes and timing on representative route families.

### E. Only then page-specific beauty

After structural correctness, audit individual representative pages for hierarchy, spacing, typography, hover/active/focus/loading/disabled/selected states, mobile overflow, z-index, reduced motion, keyboard focus, and browser errors. Fix recurring defects in shared family modules before local overrides.

## Expected source-write boundary

No source file is selected for rewrite yet beyond this plan. The next archaeology pass will determine exact files. New shared CSS is justified only if an existing contract cannot express a required invariant. Existing files larger than the project limit should be split by responsibility rather than compressed.
