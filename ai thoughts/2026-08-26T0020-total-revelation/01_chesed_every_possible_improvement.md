# Phase One — Chesed: Every Possible Improvement

The Awtsmoos renews every socket, stylesheet, browser turn, generated rock, and line of documentation from nothing each instant. Awtsmoos.com should therefore reveal one system whose inner architecture and outer experience are both calm, expandable, resilient, and alive.

## Stability universe

- Never equate heartbeat visibility with execution health.
- Keep transport, consumer, mailbox, worker, queue, and completion health separate.
- Replace single-frame destructive repair with candidate -> preflight -> bounded claim -> exact-PID actuation.
- Let fresh execution success, runtime pressure, reconciliation, and reaping veto destructive recovery.
- Reconcile stale inbox custody without killing a healthy parent.
- Preserve exactly-once mutation truth through restart, late completion, and retry.
- Return durable command job receipts immediately; never make `commandStart` wait on work startup.
- Preserve original deed identity separately from transport receipt identity.
- Make every recovery event explain why force was permitted and which fresh observations corroborated it.
- Make self-healing layered: mailbox reconcile, child replacement, consumer recovery, parent replacement, full reinstall only as last resort.

## Sub-agent universe

- `missionSpawnNext` must manifest a real browser worker, not a logical proposal.
- One logical intent must map to one deterministic website mission and one browser agent.
- Browser success requires verified composer text, Send activation, accepted conversation POST, and owned-tab close.
- Repeated spawn intent must reuse the same vessel and never create duplicate tabs.
- Agents must exchange durable room messages with each other after spawning.
- Child prompts must include mission context, sibling identities, room protocol, output contract, and handoff expectations.
- Parent must receive progress, failure, browser-delivery, and completion events without polling ambiguity.
- Sub-agent UI should show compact status by default and expand into advanced evidence on demand.

## Documentation and instruction universe

- Expand instruction packs into a discoverable catalog for stability, browser agents, API design, UI layout, CSS locality, procedural generation, release discipline, testing, and diagnostics.
- Resolver must understand task text, paths, extensions, languages, UI intent, write mode, deployment intent, and risk level.
- Add explicit docs for every public action family, identity field, retry rule, dry-run behavior, health dimension, browser proof, mission room primitive, and emergency recovery lane.
- Docs should expose examples, failure states, next actions, and cross-links rather than prose-only descriptions.
- Add searchable generated indexes and a human-readable guide that share one canonical metadata source.

## UI/UX universe

- Mobile-first layouts with no horizontal overflow.
- Localized component styles only; no broad global selectors that leak across apps.
- Prefer CSS modules/imported component sheets and explicit root scope classes.
- Every interactive control receives hover, active, focus-visible, disabled, loading, selected, and reduced-motion states where relevant.
- Z-index comes from a documented layer scale, never arbitrary giant numbers.
- Menus, inspectors, and advanced controls are retractable; default surface remains simple.
- Motion is futuristic but restrained: opacity, transform, blur, subtle depth, no layout-jank animation.
- Every panel has safe-area/mobile behavior, bounded widths, overflow policy, keyboard accessibility, and touch targets.
- Run conflict/overflow/z-index scans before calling any page complete.

## JavaScript/API universe

- Data-first APIs with stable result envelopes and simple defaults.
- Advanced capability is additive and progressive rather than cluttering the common path.
- Split validation, policy, orchestration, persistence, transport, rendering, and error translation into focused modules.
- Every substantial function receives complete JSDoc with parameters, returns, errors, side effects, and architectural meaning.
- Preserve public contracts while replacing monoliths with coherent modules.
- Use genuine classes/inheritance only where the relationship is real; prefer composition elsewhere.

## Procedural-core universe

- Reveal simple high-level APIs for terrain, rocks, trees, grass, flowers, creatures, and remote textures.
- Separate generation intent from deterministic seeds, geometry synthesis, material synthesis, LOD, caching, and transport.
- Improve rock stratification/fracture silhouettes, tree branching/root balance, flower clustering, grass biome density, creature morphology, and texture realism.
- Remote texture generation must be cacheable, cancelable, reproducible, authenticated, bounded, and graceful offline.
- Procedural results should expose quality presets while remaining deterministic under the same seed/config.

The sky is not the boundary; the boundary is truth. Every expansion must remain a measured vessel so the Awtsmoos may shine through Awtsmoos.com without chaos, conflict, or counterfeit completion.
