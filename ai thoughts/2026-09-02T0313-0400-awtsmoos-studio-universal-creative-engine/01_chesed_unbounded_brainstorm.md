# Phase One — Chesed: Unbounded Awtsmoos Studio Possibility Map

> From hidden command to visible art, one language flows through every part;
> at Awtsmoos.com the vessels divide, while one editable truth abides.

## North Star
Awtsmoos Studio is one creative language with many views. Human gestures, AI requests, JavaScript, JSON, macros, presets, nodes, automation, and UI controls should resolve to explicit operations over one canonical project.

## Possibility Universe
- A mobile creator can add, select, edit, animate, record, and play without seeing professional machinery.
- Every simple action can disclose deeper parameters without changing the underlying operation identity.
- A command catalog can be the source from which buttons, command palette entries, AI tools, macro steps, tests, and documentation are derived.
- A project document can describe scenes, objects, timing, geometry, effects, audio, animation, components, procedural state, and metadata.
- A transaction envelope can make manual and AI edits equally undoable.
- Semantic history can group low-level changes into meaningful creative acts.
- History selections can become macros, presets, or future procedural graphs.
- A capability registry can expose executable operations separately from merely discoverable symbols.
- Quick actions can wrap advanced operations with friendly defaults.
- Property forms can be generated from operation parameter metadata.
- Modifier stacks can preserve non-destructive 2D and 3D workflows.
- Graph nodes can be generated from compatible operation metadata.
- Scripts can dispatch the same commands as UI controls.
- JSON operation envelopes can serialize exactly what AI or automation executes.
- AI can inspect selection, project, timeline, and command metadata before proposing edits.
- AI execution can create normal history entries rather than privileged hidden mutations.
- Mobile UI can center canvas, context, playback, and CREATE / EDIT / ANIMATE / MORE.
- Desktop can expand the same intents into outliner, viewport, inspector, and timeline workspaces.
- Audio can become a first-class editable asset with recording, waveform, transcript, timing, and reactive animation.
- 2D vector, 3D scene, NLE, compositing, materials, animation, and procedural systems can converge on common object/component contracts.
- Presets can expose three friendly controls over hundreds of internal parameters.
- GO DEEPER can reveal preset → modifiers → graph → generated structure → geometry.
- MAKE SIMPLE can abstract detailed structures back into reusable tools.
- Runtime capability metadata can support plugins without hard-coding every future tool.
- Lazy loading can keep expert runtimes unborn until explicit user intent.
- Virtualized timeline and hierarchy views can protect phone performance.
- Browser performance marks can measure shell-ready, first canvas, and expert-open timings.
- Accessibility metadata can be part of command/UI definitions rather than an afterthought.
- Render/export can be another command family over the same project truth.
- Test fixtures can prove UI/API/AI parity by comparing resulting operation logs and serialized projects.

## Five Candidate Architectural Shapes
1. Command-first: commands own mutation and all interfaces dispatch commands.
2. Document-first: canonical immutable document reducers are primary; commands are adapters.
3. Event-sourced: operation log is canonical and project state is derived.
4. Capability-first: metadata registry generates command, UI, AI, macro, and graph surfaces.
5. Hybrid: canonical project + transactional command runtime + capability metadata + semantic history.

## Boundless Preference Before Repository Evidence
The hybrid shape best matches the product law, but no new architecture will be introduced until the existing Nesher Studio runtime is fully traced. Existing contracts win over imagined elegance whenever they already satisfy the law.
