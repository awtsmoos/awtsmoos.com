# Massive Improvement — Parallel Work Graph

> The Awtsmoos shines through many lanes at once, yet each lane keeps one evidence gate and one clear proof;  
> Awtsmoos.com lets parallel work increase truth rather than multiply races across a shared roof.

## Independent Read/Verify Lanes
A. Model Fidelity: verify 078 + affected persistence/history tests; inspect any nullish/default regressions.
B. Guard Portability: rewrite 032 under SHA, run from repo root and app root.
C. Structural Debt: enumerate >120-line JS/MJS files and compressed/minified candidates; rank by runtime centrality.
D. Mutation Islands: grep source/scene/sequence/track/clip/project state writes outside operations/commands.
E. Regression Continuation: resume full tests from 032 onward; later rerun entire suite.
F. Browser Proof: discover/start isolated static server + private Chrome debug port; collect resource/console/layout evidence.
G. Lazy Architecture: trace feature manifest, styles, demand bindings, projection disposal/idempotency.
H. Dependency Health: import cycles, stale/dead modules, unresolved imports, module-type warning source.
I. Accessibility/Mobile: inspect keyboard/focus/drag-only paths and responsive overflow contracts.
J. Handoff/Docs: record architecture decisions, evidence, deltas, and NEXT_ACTION without overwriting prior notes.

## Mutation Ordering
- No write in a lane until its current-file SHA is observed.
- New paths must be proven absent before creation.
- Existing files are always whole-file rewrites.
- Concurrent lanes may write only disjoint paths.
- If a lane discovers shared-file overlap, pause that write and merge plans before mutation.

## Verification Ordering
Focused regression first → affected subsystem suite → whole Studio suite → real browser → static architecture scans → final reread/diff.
