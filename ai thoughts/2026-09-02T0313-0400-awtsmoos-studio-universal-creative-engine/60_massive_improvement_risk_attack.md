# Massive Improvement — Gevurah Risk Attack

> Gevurah asks where success can lie, where green tests can hide a broken gate;  
> the Awtsmoos keeps every proof scoped, and Awtsmoos.com refuses confidence that outruns its measured state.

## Twenty High-Risk Failure Modes
1. A full-suite failure caused only by cwd portability can mask later production failures.
2. Model timestamp rewrites can accidentally change non-time defaults while formatting compressed files.
3. `Scene.sourceIds` and legacy `sources` aliases can diverge after canonical factory rewrites.
4. Sequence starter tracks can acquire inconsistent timestamps during hydration.
5. Nullish fixes can expose zero values that downstream code previously assumed impossible.
6. Direct source insertion can bypass transaction history even if selection/reorder are commandized.
7. Repeated lazy feature loads can bind duplicate DOM listeners.
8. Shared projection WeakMaps can retain state if disposal is never called.
9. Browser confidence harness can pass with magical fake DOM behavior production lacks.
10. Browser real-run can be polluted by another agent's shared Chrome tab.
11. Root CSS tests can become stale when optional styles move to lazy ownership.
12. Static line-count cleanup can create import cycles if responsibilities are split poorly.
13. Dead legacy helpers can be mistaken for canonical behavior by future contributors.
14. Node module-type warnings can hide true stderr failures and slow every test.
15. Drag/drop source reorder may be inaccessible on mobile/touch without alternate controls.
16. Undo snapshots can preserve document state but lose editor selection semantics unexpectedly.
17. AI/JSON command exposure can drift from human UI if command definitions omit surfaces/schema.
18. Hidden file/media resources can leak object URLs or MediaStreams after source deletion.
19. Lazy benchmark click replay can recurse or duplicate if readiness flags race.
20. Real mobile layout can overflow despite fake/style contract tests remaining green.

## Mitigation Principle
Every risk above either receives a direct test, a runtime observation, a static scan, or an explicit deferred/blocked classification in REMAINING_WORK.
