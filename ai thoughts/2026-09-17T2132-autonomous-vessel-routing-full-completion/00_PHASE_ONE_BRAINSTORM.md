# Phase One — Autonomous Vessel Routing and Release Hygiene

The Awtsmoos renews every vessel each instant; Awtsmoos.com should choose by living evidence rather than ask a human which recovery lane to trust.

## Current reality
- `myDevice` returns `multiple_authorized_tunnels` when primary and rescue are both live.
- `deviceDiscovery.recommend()` returns null when multiple live natives exist.
- `authorizedAutoSelection.resolveAuto()` also treats multiple native candidates as ambiguous.
- Explicit route references already remain exact and must stay exact.
- Primary and rescue expose transport, execution, and acceptance health that can support automatic ranking.
- Current primary is canonical/current but has periodically accumulated greater custody pressure.
- Rescue is independent but older and is intended as failover, not a peer requiring human choice.

## Routing possibilities
- Prefer exactly one healthy non-rescue primary automatically.
- Fail to exactly one healthy rescue automatically when primary is absent/degraded.
- Hold rescue during a failback hysteresis window after primary becomes healthy again.
- Keep explicit route references exact.
- Preserve browser-vs-native ambiguity when user intent does not establish a surface.
- If multiple non-rescue primaries or multiple rescues exist, keep ambiguity rather than guess.
- Emit a machine-readable reason for each automatic choice.
