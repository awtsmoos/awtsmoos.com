## Root causes + fixes
1. **Search filter** — cascade layers. `css/future/interaction/controls.css`
   (layer awt.controls, AFTER awt.views) set
   `:where(button):not(...){display:inline-grid}` on every shell button.
   Layer order beats specificity, so it defeated the views-layer
   `.awt-action-option[hidden]{display:none}`. Fix: generic pill rule now
   excludes `.awt-action-option` and `.awt-runtime-entry`, and a
   `[hidden]{display:none!important}` guard was added in BOTH the controls
   layer and the new polish-layer beauty file.
2. **Detail pane params** — selection only *dimmed* fields (is-muted =
   opacity .46), so every action showed every field and Run drowned.
   `actionSelection.js` rewritten: `visibleFieldsFor(item)` computes the
   action's real field set from its catalog defaults (path/maxChars only
   when the action declares a path; website-mission fields only for
   website-mission actions); irrelevant labels are hidden outright, detail
   scrolls into view, Run (existing dispatch through buildOptions/callFs)
   stays visible. Unit-tested.
3. **Textareas** — every textarea forced min-height:120px and, with all
   fields always visible, the detail pane was a stack of huge dark boxes.
   Fixed by (2) plus min-height 88px and the beauty layer's champagne
   focus/ink treatment.
4. **Disclosures** — native summary toggling was unreliable in the live
   shell. `mountUsage` now binds each `.awt-output-details` summary to
   toggle its details element deterministically (dataset-guarded), and
   Load usage still opens + fills its box (fixture asserts the box content
   changes and the details opens).
5. **Sidebar nav** — two real defects: (a) `workspace.css` set
   `.awt-workspace-mode .awt-dashboard{display:none}` (awt.views) defeating
   the viewport shell contract (awt.reset) that keeps the dashboard as the
   112px rail in workspace mode — in a workspace the rail was dead, so
   sidebar switching/Return-home depended on a hidden dashboard. Rule now
   `display:grid` per the shell contract; fixture asserts the rail and nav
   are visible in workspace mode and every key + both home routes switch.
   (b) The same layer-beats-hidden bug as (1) corrupted button states.
   NOTE: in the shell-only fixture all 21 keys already switched pre-fix;
   the live failures are attributed to (a) + the live repair/observer
   stack, and the rendered re-check is the arbiter.
6. **Diagnostics** — the drawer/toggle existed but
   `css/future/views/no-side-rails.css` explicitly display:none'd
   `.awt-diagnostics-drawer` and `.awt-diagnostics-toggle` under
   `body.awt-no-side-rails` (which mountShell always adds), and no nav
   entry opened the drawer. Fix: diagnostics selectors removed from the
   kill list (drawer is not a side rail), and a real **Diagnostics button
   in the navigation grid** (navigation.js) that collectDiagnostics() +
   opens the drawer with the live agent/server/connectivity outputs the
   collector already gathers.
7. **Runtime mesh** — tiles showed name/mode/"." (activeRoot). New
   dependency-free `runtimeStatus.js`: virtual-os → online, native →
   tunnel.connected ? online : offline, otherwise **unknown** (never
   invented). Tiles show status (+ root when meaningful), and the active
   runtime's detail (health, graph, mounts, timeline) now opens WITH the
   panel instead of hiding behind a click. Pane description corrected to
   match reality.
8. **Vessel JSON contradiction** — client projection layer
   (`discoverySanitizer.js`, the JSON the Account panel prints):
   `sourceOk: raw.ok !== false` sat beside `connected:true` whenever a
   partial source failure still delivered a connected device. Now
   `sourceOk = raw.ok !== false || Boolean(recommended)` and the partial
   failure is carried honestly as `sourcePartial:true` + warnings.
   Unit-tested with the route-selection fixture device.
9. **Agent-room FAILED spam** — one cycle of a status sweep (chatgptStatus,
   websiteAgentMissionList, aiAgentList, tunnelPlanList, macSpeakerState,
   configGet, chromeFind) against devices with no live heartbeat re-printed
   the same FAILED line ~every minute. The dispatches are real (recorded
   by the room), the spam is in the feed rendering: new
   `groupRepeatedFailures` in liveRoom.js folds identical failed
   dispatches (same agent + content) into ONE counted row at first
   position — "repeated N× · device appears offline" when the error says
   so, with the first–last time span. Single failures untouched, nothing
   hidden. Unit-tested (3 identical failures → 1 row, count 3).
