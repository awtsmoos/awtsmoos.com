## Per item

1. **Status bar clipped in the full Live agent room** — measured root:
   `css/viewport/pages.css` makes `.awt-pane-content` a card-deck GRID
   (`repeat(auto-fit, minmax(min(100%,260px),1fr))`, definite height). The
   room panel is a tall single panel, not a deck card: as a grid item its
   box was capped at the pane-content height (**628px**) while its content
   needs **~995px** (panel grid rows summed 42+499+84+134+99+41 + gaps +
   padding). Inside the panel's `.stack` grid the first row computed to
   42px and the status notice (glass `overflow:hidden`, margin-bottom
   16px) was squeezed to 42−16 = **26px** — half its 51px content height —
   so its own overflow clipped the glyphs (screenshot: only the lower half
   of "Live · 1 agents online · 100 recent entries" visible). The panel's
   bottom rows (name/message/composer) were clipped the same way, and the
   pane-content never scrolled (scrollHeight == clientHeight: clipped
   content inside the panel is unreachable). This is a different container
   path than the home card run 09 fixed. Fix (`css/run10-fixes.css`,
   unlayered, imported last): in the liveRoom pane the pane-content is a
   plain block scroller (`display:block`) — the panel sizes to its
   content and the pane scrolls — and `.awt-room-panel > .notice` gets
   `min-height: max-content` so no future row squeeze can halve it again.
   Evidence (1919×998): status height 26 → **51px**, text Range rect fully
   inside the notice box (16px clear top and bottom), status offset in
   panel 17px (padding), panel now contains every row (panel height
   1,023px, last child bottom inside panel bottom), pane-content scrolls.
   At 390×844: status 77px (3 wrapped lines, all inside), panel contains
   all rows.
2. **Home grid overlaps room card controls** — measured root (1919×998):
   the dashboard grid sized its rows to **434px/400px** while the room
   card paints **572px** tall — the card overflowed its row by ~138px
   onto the launcher grid's row; tile #4 overlapped the message input by
   **4,410px²**. At 390×844 the launcher grid's own `max-height:100%` +
   `place-content:center` + `overflow:hidden` additionally centered its
   ~756px of tile rows into a 359px box — rows spilled above the box
   (clipped, unreachable), tiles overlapped Send by 1,890px² and the
   "Open full room" link by 1,710px², and the home feed was squeezed to
   0px tall. Fix (run10 sheet, home mode only): the dashboard is a flex
   column (`display:flex; flex-direction:column; align-items:center`),
   card and launcher are `flex: 0 0 auto` (never shrink below content),
   and the launcher grid loses its cap (`max-height:none;
   overflow:visible`); the dashboard's existing `overflow-y:auto`
   (run 08) scrolls to whatever does not fit. Evidence: at both
   1919×998 and 390×844 — tile overlap with card, message input, Send
   and Open-full-room all **0px²**; elementFromPoint at Send and at Open
   full room returns the controls themselves; home feed height 339px
   (1919) / 287px (390, was 0); home status bar still fully inside its
   card with glyphs uncut (run-09 item 5 home half: no regression).
