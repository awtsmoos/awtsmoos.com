## Per item

1. **Last non-gold accents** — the navy lived in
   `css/future/surfaces/glass.css`, which paints `.notice`, `.panel`,
   `.awt-mesh-node` etc. with `linear-gradient(rgba(13,29,50,.82),
   rgba(5,13,26,.90))` + blue/violet radials. Runs 07/08 re-based the shell
   chrome but never the glass surfaces, so (a) the room status bars
   (`#liveRoomStatus`, `#homeRoomStatus`), (b) the mission-room banner
   (`#roomStatus`) and (c) the runtime graph nodes (`.awt-mesh-node`) all
   computed navy in the harness. The 'system' badge was
   `.awt-pane-icon.is-system`: run 08 set the icon INK gold but the chip
   backgrounds stayed per-group tints (blue core, pink ai, green files,
   violet system — all measured). Fix: new unlayered `css/run09-fixes.css`
   (imported last in app.css) re-bases `.notice` + `.awt-mesh-node` to
   espresso/gold gradients with a gold sheen ::before, and every
   `.awt-pane-icon` variant to gold ink on `rgba(255,182,74,.14)`.
   Evidence (computed styles, harness): all three notices and the mesh
   node now compute gold gradients; all five pane-icon variants compute
   `rgb(255,207,94)` on `rgba(255,182,74,0.14)`; no navy/blue/violet/pink/
   green values remain on any of them.
2. **One no-op sidebar click from the agent room** — the feed was ruled
   out by measurement: across 4 dwell cycles + a 15-click randomized-phase
   stress (presses landing inside the room's 3s re-render), the nav button
   node was never replaced (identity stable) and no click was eaten
   (19/19 switched). The proven defect in the exact path: navigation had
   TWO owners — every destination button and launcher tile carried its own
   click listener AND `bindNavigationButtons`' delegated document
   listener, so each click fired `activatePane` twice (measured: two
   `awt:pane-change` events per click), and the binding itself had no
   re-entry guard. Fix: navigation is owned solely by the delegated
   handler — one-time guarded, resolves the destination via `closest()` at
   click time (immune to node replacement), handles Home (`data-awt-home`
   → `showHome()`) and closes the nav after switching; the per-button and
   per-tile listeners are removed (`navigationControls.js`,
   `dashboardCard.js`). Evidence: 10 consecutive FIRST-click switches from
   liveRoom (mesh, usage, account, docs, apiKeys, explorer, setup, plans,
   live, terminal), each producing exactly ONE pane-change.
3. **Stale Action URL** — `actionUrlOut` was written only inside
   `runSelectedAction`, i.e. it froze at the last EXECUTED action. Fix
   (`js/features/actions.js`): `bindActionUrlPreview` rebuilds the URL
   from the pane's live fields (`buildOptions` + `buildFsUrl`) on catalog
   selection (grid click listener — bubbles after the card's own selection
   handler applies the new fields) and on any field input/change.
   Evidence: real clicks list → browserDoctor → agent produced three
   distinct URLs each naming its action (`action=list|browserDoctor|
   agent`); editing Path to /tmp/xyz updated `p=` in the preview.
4. **Heading overlap** — measured root: `.awt-detail-head` was grid
   `minmax(0,1fr) auto` inside a ~245px column; the badge (group + badges,
   ~235px) ate the row and the title column computed to **0px**
   (`grid-template-columns: 0px 234.5px`), so long titles painted over the
   pill. Fix (run09 sheet): the head is a wrapping flex row — title
   `flex:1 1 12rem; min-width:0`, badge `flex:0 1 auto` with wrapping, so
   the pill drops to its own line when the row cannot hold both.
   Evidence: title width 245px (was 0), overlap area 0 for 'Start ChatGPT
   website team' and 'Message website agents' at desktop AND 390px.
5. **Feed status bar clipped** — measured root at the original viewport
   (1919×998, full 100-entry feed): the home dashboard
   (`css/viewport/home.css`) is `place-items:center; overflow:hidden`;
   the room card (572px) taller than its grid row was centered, so it
   overflowed the row UPWARD — card top at **−6px**, above the dashboard's
   top edge, clipped, and unreachable by scrolling (centered-grid
   scrollport trap). Fix (run09 sheet, home mode only):
   `place-items:start center; align-content:start; grid-template-rows:
   none; grid-auto-rows:auto` — rows size to content, anchored at the top;
   the dashboard scrolls downward instead of clipping upward. Evidence:
   same conditions now give card top 63px (dashboard top 38px), status bar
   fully inside the card (78–129 of 572) and topmost at its own point.
