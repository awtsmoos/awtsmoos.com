# Gevurah — Real Repository Performance Boundaries

The Awtsmoos gives every possible light, but Awtsmoos.com must measure what the browser is asked to carry;
magic becomes trustworthy only when motion is bounded, tactile, reversible, accessible, and never heavy.

## Risks now proven or likely

- `motion.css` already owns reveal and hover lift; adding active/focus/icon logic there would mix responsibilities.
- Apps has concurrent drift, so any rewrite must preserve its exact newer catalog contract rather than restore prior copy.
- Generated Games `.gameCard` and Apps `.g-app-card` already inherit shared surface treatment; tactile states must compose with their own route CSS.
- Pointer aura is JavaScript-driven; new effects should be CSS-only unless JavaScript adds unique value.
- Social already owns a mature nebula/icon language and should receive only compatible shared interaction tokens.
- Wallet contains forms; no ambient renderer or aggressive hover movement belongs behind form interaction.
- A procedural layer is forbidden until the real renderer source and lifecycle contract are found.

## Performance covenant

1. Animate compositor-safe `translate`, `scale`, `rotate`, and opacity only for tactile motion.
2. Hover lift remains <= 2px on ordinary surfaces and <= 3px on major CTAs.
3. Active press uses `scale: .985` or equivalent tiny compression and returns immediately.
4. Focus-visible remains obvious even with all animation disabled.
5. No idle-loop icon animation.
6. No persistent `will-change` on grids.
7. No JavaScript magnetic buttons unless browser evidence proves CSS insufficient.
8. No layout reads inside hot pointer loops beyond the already bounded aura controller.
9. No WebGL import on Wallet, Social, Home, OS, or Torah.
10. Games is the only first candidate for a procedural hero.
11. Apps can only receive procedural enhancement after Games proves clean.
12. Reduced-motion must remove nonessential transforms and all procedural initialization.
13. Hidden tabs and offscreen heroes must pause any admitted renderer.
14. One renderer, canvas, and animation loop maximum per page.
15. Device-pixel ratio capped at 1.25 by default.
16. Sparse points/lines only; no textures or postprocessing.
17. Particle target 28–72 depending on viewport/capability.
18. Frame-pressure policy must reduce density before shutdown.
19. CSS fallback remains the complete default experience.
20. If repository evidence does not support a safe reusable renderer, WebGL is rejected for this pass.

## New module boundaries

- `interaction.css`: hover, active, focus-visible, press feedback, CTA sheen.
- `icon-motion.css`: semantic SVG micro-motion only.
- `performance.css`: only proven low-risk rendering hints such as catalog `content-visibility`.
- `motion.css`: remains reveal/elevation lifecycle; may be rewritten to remove tactile responsibilities if duplication would result.
- `index.css`: import manifest only.

Conditional JavaScript only after renderer proof:

- `FuturePerformanceGovernor.js`: capability/frame-budget policy.
- `FutureVisibilityGate.js`: page/hero visibility lifecycle.
- `FutureProceduralLayer.js`: renderer adapter only.
- `FutureProceduralCoordinator.js`: composition only.

## Verification boundary

Before completion, every touched source file must be read completely, remain tab-indented and under the file ceiling, pass syntax/tests/diff checks, and preserve current business routes and data mounts. Browser checks must cover hover, active, keyboard focus, reduced-motion, and any admitted procedural lifecycle.

Gevurah decides that speed is not one feature among many; speed is the vessel that allows every other future effect to remain believable.
