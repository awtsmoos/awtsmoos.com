# Phase One — Chesed: Every Plausible Failure and Repair Shape

The Awtsmoos creates the pulse and the pause anew; Awtsmoos.com therefore treats every stale witness as a vessel, never as the Essence of truth. A watchdog may see darkness while fresh work is already rising; a sub-agent may exist in a ledger while no browser ever breathed.

## Crash universe

- A stale child snapshot can mature a consumer-stall candidate just before fresh parent progress arrives.
- The current same-observation claim can turn old evidence into immediate SIGTERM authority.
- A single stale parent-custody record can outlive its real action and look like orphaned work.
- Mailbox raw health can degrade while execution remains healthy and recentSuccess is true.
- Runtime pressure can temporarily raise lag or leave active custody without implying a wedged consumer.
- Parent pulse can be stale because the parent event loop was delayed, not dead.
- Connection child IPC can be stale while the parent is healthy, requiring child-only replacement.
- Durable repair cooldown can prevent storms but cannot validate whether the repair itself is still necessary.
- A ledger claim should be an authorization reservation, not proof that the condition remains true.
- Restart should preserve accepted inbox/outbox evidence and exact-once reconciliation.
- Old/stale custody should be reconciled/quarantined independently from parent process death.
- Destructive repair should be the last stage after detection, corroboration, preflight, and final veto.

## Sub-agent universe

- Logical child creation is not browser manifestation.
- `continuity.spawnMissions()` currently creates only `status: proposed` children.
- The website spawn path already waits for browser proof, but generic mission actions never call it.
- A stable bridge must map each proposed mission child to one deterministic website mission/spawn request.
- Duplicate missionSpawnNext calls must reuse the same child and must never open duplicate tabs.
- Success must require composer verification, real Send activation, matching conversation POST, HTTP acceptance, durable event, and owned-tab close.
- Pending browser delivery must remain pending, not be converted into logical success.
- Browser failure must preserve the proposed mission child for diagnosis/retry without creating another identity.
- Mission auto-spawn must remain bounded under pressure and must not starve P0/P1 recovery actions.

## Ideal architecture

Detection is Chesed seeing possibility. Preflight is Gevurah refusing premature force. Tiferes authorizes one repair only when both agree. Mission intent is Chochmah; website mission state is Binah; the physical browser POST is Malchus. No earlier world may impersonate the final manifestation.
