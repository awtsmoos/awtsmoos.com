# Chesed — Stability Universe

The Awtsmoos keeps one deed beneath changing sockets; Awtsmoos.com must let recovery remain reachable precisely when ordinary work is pressured.

## Observed failures

- One terminal outbox envelope has survived roughly eight hours while transport and execution remain healthy.
- Duplicate terminal responses are already ACKed by the relay after valid durable correlation.
- Therefore the ancient envelope is not a generic missing-retry problem; it is a specific settlement/correlation failure.
- Mailbox status/export/quarantine are marked P0 but still wait behind the ordinary action consumer.
- Tiny grep and mkdirp requests can be classified into p4_bulk and expire before a consumer starts.
- Reads/lists can queue despite ready filesystem workers, proving lane admission and executor availability can diverge.
- Completed command-job output may still queue in p0_observe instead of being served directly from durable storage.
- Transport failures separately show socket closure followed by retryable upstream HTTP 502 websocket handshakes.

## Ideal architecture

1. Keep exactly-once result preservation absolute: never delete terminal outbox data because it is old.
2. Let the relay ACK an already-committed exact terminal envelope when immutable receipt/result identity proves equivalence.
3. Let periodic mailbox maintenance notice stalled outbox separately from stale inbox custody.
4. Keep result-bearing ambiguity preserved; escalate or replace generation only when exact settlement cannot be proven.
5. Route mailbox/native-generation emergency actions through a controller-owned bypass that does not require ordinary action consumption.
6. Serve durable command status/output and emergency evidence directly from controller-owned stores where possible.
7. Classify interactive filesystem work by actual cost: grep/find/stat/list/read/mkdirp must never inherit bulk solely from broad action grouping.
8. Keep bulk writes/batches in bounded bulk lanes, with fairness so queued work cannot coexist indefinitely with idle capacity.
9. Treat upstream 502 reconnects as transport/proxy events; never convert them into local execution failure or destructive replacement.

The light of Chesed is not force but continuity: the Awtsmoos lets each safe witness flow, while Awtsmoos.com refuses both silent data loss and unnecessary death.
