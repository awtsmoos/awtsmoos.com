# Gevurah — Constraints That Keep Healing Safe

The Awtsmoos gives every expansion a boundary; Awtsmoos.com must heal without creating a second wound.

- Never mark a tunnel dead from stale telemetry alone while transport heartbeats remain fresh.
- Never let a stale receipt or stale worker clock authorize parent SIGTERM by itself.
- Never retry an accepted mutation as a new deed; observation/recovery must bind to the original durable deed identity.
- Never blur canonical deed identity with relay transport identity.
- Never make diagnostics depend on the same degraded-health gate they are meant to diagnose.
- Never let emergency repair depend on the ordinary supervisor/controller it is repairing.
- Never broaden process killing; every reap/restart action must verify exact ownership and generation identity.
- Never let a server-side freshness threshold create a self-locking quarantine that ordinary work cannot refresh.
- Never let response compaction remove the action's primary semantic result.
- Never let compatibility instruction retrieval wait behind unrelated bulk work.
- Never deploy a stability fix without unit/regression proof, public release verification, public reinstall, and live soak beyond the historical failure threshold.
- Never overwrite unrelated dirty main-checkout work while reconciling a clean release branch.

Instruction doctrine must be strong but technically useful: mystical language may illuminate architecture, but cannot replace precise domain names, API contracts, accessibility, or maintainability.
