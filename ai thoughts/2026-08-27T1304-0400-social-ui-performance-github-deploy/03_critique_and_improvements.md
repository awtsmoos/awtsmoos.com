# Tiferes Critique — Improvement Ledger

Boruch Hashem. Blessed is He.

Tiferes asks whether speed, beauty, and preservation truly agree on Awtsmoos.com. The following improvements constrain the first instinct with verification.

1. Measure before optimizing.
2. Compare compact and non-compact output rather than assuming minification wins.
3. Check whether compact mode changes cache headers or MIME behavior.
4. Ensure compact mode never rewrites JSON/data responses unexpectedly.
5. Separate transfer-size wins from parse/execute cost.
6. Count CSS imports and request waterfall depth.
7. Remove only legacy layers proven redundant.
8. Keep accessible focus behavior through disclosure menus.
9. Test keyboard as well as pointer interactions.
10. Test narrow height as well as narrow width for fixed action bars.
11. Check safe-area handling.
12. Check long labels and errors.
13. Check preview body scroll lock.
14. Ensure More menu does not clip behind fixed bars.
15. Ensure Tools/Sections menus do not create horizontal overflow.
16. Test Advanced mode does not reopen all panels.
17. Test desktop Advanced can still intentionally maintain multiple panels.
18. Inspect network 404s after cache busting.
19. Inspect console warnings that may reveal contract drift.
20. Audit adjacent social routes through real route discovery, not names alone.
21. Keep shared clarity tokens local until reuse is proven.
22. Inspect all dirty files before blanket commit.
23. Use secret scan plus targeted review of suspicious untracked files.
24. Preserve unrelated tests/docs/source even when outside this UI mission.
25. Exclude dependency/build caches unless project policy explicitly tracks them.
26. Verify remote main state before push.
27. Pull/fetch and compare origin/main before integrating to avoid overwrite.
28. Never use force push to solve divergence.
29. Discover production deployment from scripts/docs/recent history.
30. Verify production revision and page response after deploy.
31. Record public cache headers and compact behavior after publish.
32. Re-run smoke tests against production, not only localhost.
33. Update REMAINING_WORK after every discovered failure.
34. Re-read touched files after any fixes.
35. Close only when no safe user-visible/performance/deploy work remains.
