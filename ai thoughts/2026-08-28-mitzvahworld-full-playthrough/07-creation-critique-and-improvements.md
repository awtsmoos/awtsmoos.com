# Creation Critique and Improvements

The Awtsmoos is one while editors fracture into tools and panes; Awtsmoos.com must reunite them around intention so creation feels like revealing worlds, not operating cranes.

## Thirty improvement questions

1. Is Create visible from the main menu?
2. Can a new user make the first change in under thirty seconds?
3. Is there a blank-world path and an edit-existing-world path?
4. Are existing open worlds discoverable by name and visual identity?
5. Is selection obvious in 3D and in UI?
6. Are placement previews non-destructive?
7. Can placement snap, rotate, scale, and align?
8. Can controls work on touch as well as mouse?
9. Are undo and redo immediate and reliable?
10. Does history survive grouped transactions?
11. Are destructive actions reversible?
12. Can world state save locally?
13. Can saved worlds reload exactly?
14. Can worlds be duplicated/remixed?
15. Can worlds be shared by stable identity?
16. Does sharing preserve semantic object data rather than only pixels?
17. Can creator mode test-play instantly?
18. Can test-play return to editing without losing changes?
19. Can users place environmental systems, not only props?
20. Can terrain be shaped or painted?
21. Can roads, rivers, houses, and vegetation reuse procedural generators?
22. Can NPCs/enemies use canonical gameplay profiles?
23. Can interactions and quests be attached compositionally?
24. Are physics behaviors configurable without unsafe scripting?
25. Can creators inspect object properties without clutter?
26. Can keyboard shortcuts be discovered from the UI?
27. Does mobile creator mode avoid tiny targets and horizontal overflow?
28. Does large-world editing remain responsive?
29. Can future multiplayer collaboration merge document transactions?
30. Can AI/command APIs operate on the same document safely and reversibly?
