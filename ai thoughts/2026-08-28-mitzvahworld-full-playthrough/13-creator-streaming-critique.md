# Creator Streaming Critique

The Awtsmoos remains one when every object sleeps or wakes; Awtsmoos.com must prove that persistence, streaming, and editing share truth rather than accumulating convenient mistakes.

## Thirty checks before release

1. Is imported JSON parsed before any live mutation?
2. Is schema identity checked exactly?
3. Are unsupported versions rejected clearly?
4. Are duplicate object IDs rejected?
5. Are transforms finite numbers?
6. Are object dimensions bounded away from zero?
7. Are absurd coordinates handled without freezing the browser?
8. Are unknown primitive kinds rejected or preserved safely?
9. Does save produce deterministic portable JSON?
10. Does reopen preserve object IDs?
11. Does remix create a new world identity?
12. Does remix preserve source provenance?
13. Does import leave the old session intact if validation fails?
14. Does import roll back runtime mounts if one collider fails?
15. Does local persistence survive reload?
16. Does local persistence failure degrade to export/share rather than crash?
17. Are authored objects indexed by global coordinates?
18. Can one document span many cells?
19. Are distant cells unmounted from scene and octree?
20. Can the edited cell be pinned so a ghost/selected object never disappears?
21. Does walking back remount exact semantic objects?
22. Is cell streaming idempotent?
23. Does streaming avoid duplicate meshes/colliders?
24. Can built-in Kedem and creator overlays overlap without authority conflict?
25. Does world startup cost stay independent of creator document size when no custom world is open?
26. Does opening a large creator world avoid mounting everything at once?
27. Are mobile touch controls still at least 48px where practical?
28. Are Save/Open/Remix discoverable without cluttering play mode?
29. Can future multiplayer transactions target the same object IDs?
30. Does every failure leave diagnostics and a clear recoverable next action?
