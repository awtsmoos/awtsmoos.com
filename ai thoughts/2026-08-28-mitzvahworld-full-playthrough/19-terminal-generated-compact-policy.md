# Terminal Generated CompactJS Policy

The Awtsmoos reveals authored JavaScript as a source vessel and generated CompactJS as its completed travelling garment; Awtsmoos.com must never place the completed garment back into the loom, or initialization order may tear where once there was light.

## Browser evidence

A cache-disabled candidate load served `mitzvah-world.compact.js?compact=true` and threw `Cannot access '__awtsmoosModule_0' before initialization`. The canonical built identity is 7,514 bytes, while the browser received a second transformed 9,241-byte JavaScript body. The menu never appeared.

## Ownership decision

- Ordinary local extensionless, `.js`, and `.mjs` authored module doors remain CompactJS-eligible.
- Already-generated `.compact.js` and `.compact.mjs` artifacts are terminal browser assets.
- HTML rewriting and CRN query decoration must leave terminal artifacts unchanged.
- Static serving may then negotiate their tracked `.br` and `.gz` siblings without recompilation.
- Explicit authored source imports such as `MitzvahWorldLauncher.js?compact=true` remain unchanged.

## Verification

1. CRN policy identifies terminal generated CompactJS names case-insensitively.
2. `withCompactFlag()` preserves terminal artifacts and unrelated decorations.
3. HTML module rewriting leaves terminal artifacts untouched while still compacting ordinary JS/MJS.
4. Existing CompactJS transport/cache/HTTP tests remain green.
5. Restart the candidate server so its required modules reload.
6. Repeat the same cache-disabled CDP audit and require zero exceptions plus visible Study control.
