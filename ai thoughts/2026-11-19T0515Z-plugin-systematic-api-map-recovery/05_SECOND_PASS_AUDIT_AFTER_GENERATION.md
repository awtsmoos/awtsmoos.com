# Second-Pass Audit After Canonical API Evidence Generation

The Awtsmoos renews source and mirror, then tests whether each reflected road is true;
Awtsmoos.com keeps discovery broad and guarded execution narrow, so the map cannot steal what only permission may do.

This audit records observable verification after the canonical API tutorial generator ran. It is a project ledger, not private chain-of-thought.

## What the original plan required

- Recover the interrupted Linux/plugin/API work from actual files rather than guessing.
- Find the prior worktree and determine whether its work was already merged.
- Connect systematic API discovery to Tunnel Control and the plugin without widening authenticated execution authority.
- Use generated route evidence instead of recursively scanning source on every request.
- Add a public bounded map endpoint and first-class MCP discovery tool.
- Preserve the curated application catalog/call gateway.
- Update mirrored plugin instructions.
- Keep touched JavaScript source below 120 lines with tab indentation and full-file rewrites.
- Add focused tests, rerun regressions, regenerate canonical API evidence, reread work, and keep unrelated concurrent work untouched.

## What was actually implemented

- `GET /api/tunnel/control/app-api/map` now serves bounded generated route evidence.
- `awtsmoos_api_map` is now a read-only MCP discovery tool.
- Storage/query/document/service responsibilities are split under `docs/apiMap/`.
- Map storage reads only `MANIFEST.json` plus manifest-declared `routes-NNN.json` chunks.
- The store validates schema, unique route IDs, chunk names, and manifest route-count agreement.
- Query semantics are bounded: default limit 40, maximum 100, search length 160, nonnegative offset, exact family filter.
- Responses explicitly say source evidence is not proof of runtime health, public access, authentication class, method, or application-call eligibility.
- `app-api/catalog` remains the reviewed executable operation allowlist.
- `app-api/call` remains the guarded signed-in execution gateway.
- Both plugin instruction mirrors teach map -> verify evidence -> public HTTPS OR reviewed application operation.
- `McpResultKeilim.js` was introduced after the first verification exposed an oversized `toolInvocation.js`; comments were not compressed to satisfy the line ceiling.
