# Capability Phase Two — Gevurah: Twenty Boundaries Before Metadata Becomes Another God-Object

The Awtsmoos renews every possible command while Gevurah measures the vessel that may name it; Awtsmoos.com keeps discovery honest so metadata illuminates real power instead of inventing a shadow API beside it.

1. Preserve every existing direct Nature verb and signature.
2. Keep `NatureCatalogApi` focused on authoritative value/species catalogs.
3. Put operation/capability discovery in its own adjacent registry, not inside species catalog definitions.
4. Capability records describe execution; they never call specialist authorities.
5. Every `path` must resolve to a real current public verb or domain method proven from source.
6. Do not duplicate preset arrays already owned by specialist catalogs; reference the owning catalog/domain instead.
7. Do not duplicate dynamic provider availability; expose a requirement flag and let runtime API report installed provider state separately.
8. Distinguish synchronous creation, asynchronous generation, planning, and runtime-returning operations.
9. Distinguish simple/default fields from advanced/expert groups for progressive disclosure.
10. Keep input descriptors renderer-neutral and serializable so UI/docs/automation can consume them.
11. Do not embed functions inside public capability records; immutable plain data is easier to serialize, test, and document.
12. Preserve deterministic seed semantics as metadata only when the underlying operation uses Nature call context or a proven deterministic planner.
13. Preserve quality/realism support only when underlying facades actually honor those defaults/options.
14. Remote texture metadata must never imply a provider exists when `textureGenerator` was not injected.
15. Aliases are only recorded when a real API compatibility alias exists, such as `surface` for `material` or `biome` for `world`.
16. Search must operate on stable ids, labels, families, tags, and paths without fuzzy hidden dependencies.
17. Filter APIs should accept family/level/execution-kind/provider requirements without mutating canonical records.
18. Unknown ids must throw a vocabulary-rich `RangeError`; optional lookups may use `has()` before `get()`.
19. Split record creation, registry data, query logic, and public facade into separate modules before any file approaches 120 lines.
20. Capability tests must compare descriptor paths against an actual `NatureApi` instance so metadata cannot silently drift from executable API.

## Failure reconstruction

- Metadata drift: caught by path-resolution contract tests.
- UI clutter: simple/advanced group separation is structural data, not CSS convention.
- Duplicate API: records contain no execution functions and existing verbs remain canonical.
- Network surprise: async generated-surface capability declares provider dependency explicitly.
- Schema sprawl: descriptors use a small common shape with optional detail groups.
- Catalog confusion: species/value catalogs remain in `NatureCatalogApi`; operations live in `NatureCapabilityApi`.
- Future generator growth: each family can add descriptor modules without editing one enormous registry file.
