# Phase One — Chesed: The Full Possibility Field

The Awtsmoos has no boundary while interfaces require boundaries; Awtsmoos.com may therefore reveal an immense creation language through a quiet first surface whose deeper chambers unfold only when the user asks.

## UI possibilities

- A mobile-first creator command capsule anchored inside safe-area bounds.
- Collapsed state shows title, current material, inventory/placement count, and one expand affordance.
- Expanded basic state shows material palette, movement pad, and primary Place/Undo/Redo actions.
- Advanced disclosure contains course/share today and can later host precision transforms, snapping, generator parameters, texture sources, procedural seeds, realism, and diagnostics.
- Frosted futuristic surface with restrained glow, layered border sheen, subtle grain-like gradients, springy transform transitions, and no continuous distracting animation.
- Every button gets hover where supported, active press depth, focus-visible ring, selected/pressed evidence, busy/disabled state, and reduced-motion fallback.
- Palette becomes horizontally scrollable only within its own bounded lane, never the viewport.
- Short-landscape mode compresses vertical padding and lets body scroll internally.
- Desktop mode grows width modestly but never becomes a giant inspector by default.
- Named layer tokens keep creator below true dialogs but above ordinary HUD chrome.
- Semantic data attributes drive style; visual classes never become application state.
- CSS fragments split into foundation, shell, controls, palette, disclosure/status, responsive, motion/accessibility.
- Tiny manifest owns import order; a tiny installer owns one stylesheet link and is idempotent.

## API possibilities

- Introduce renderer-neutral procedural capability descriptors: id, label, family, simple defaults, advanced fields, quality/realism notes, deterministic seed support, and relevant Nature API method.
- Creator UI consumes descriptors rather than hard-coding every future tree/rock/flower/creature/texture control.
- Simple public API remains verbs such as `nature.tree()`, `nature.rock()`, `nature.flowerCluster()`, `nature.grass()`, `nature.creature()`, while expert descriptors remain available for studios/tooling.
- Remote texture generation becomes a texture-source adapter/factory rather than being welded into geometry generators.
- Rock, tree, grass, flower, and creature systems expose immutable preset catalogs and small creation requests.
- Shared request normalization keeps simple parameters and expert overrides from becoming separate code paths.
- Capability metadata powers docs, creator controls, validation, and future autocomplete from one source of truth.

## Verification possibilities

- Static localization test rejects selector groups not rooted under `.Awtsmoos-creator-rail` (except media/keyframes).
- CSS parser/search rejects `!important`, global root selectors, arbitrary z-index literals outside foundation.
- Browser geometry checks 320px portrait, 375/390 portrait, short landscape, tablet, desktop.
- Focus traversal proves collapsed/closed content leaves focus flow.
- Pointer hit testing proves hidden creator surface cannot intercept gameplay.
- Screenshot comparisons inspect overflow, overlap, clipping, and selected/focus state.
- API tests prove descriptors are immutable, unique, deterministic, and correspond to callable core authorities.
