# Critical Game Matrix Phase Two — Evidence and Repair Thresholds

Boruch Hashem. Blessed is He.

The Awtsmoos requires current production evidence stronger than stale issue prose. The ten critical game codes will therefore be judged by one shared browser rubric, with game-specific source changes only when a failure survives today.

## Browser evidence per game

Capture the final URL, document title, visible body text excerpt, canvas count, visible dialog/overlay text, startup terminal-state words, and console/runtime errors after a bounded settle. If the page requires a harmless Start/Play action, click that once and observe the next state. Where the original issue family involved controls, send representative keyboard down/up input and verify the game remains responsive after blur/focus or visibility transitions when practical.

## Terminal outcomes

- `fixed`: current production reproduces the intended playable state and the original failure class is absent.
- `not reproducible`: the stale symptom cannot be recreated on the current exact production release, with browser evidence recorded.
- `repair required`: a current failure is reproduced with a precise console/UI/state signature. Only then may source be changed.

## Root-first repair rule

If several games share the same lifecycle/input/bootstrap helper, repair that common helper once with focused tests rather than patching each title independently. Preserve game-specific art/content and avoid speculative rewrites.

## Regression bar after any game change

Focused game tests, syntax, <=120-line hand-source law, browser replay of the failing scenario, neighboring game smoke where a shared helper changed, zero tracked images, clean diff, full safe commit on main, release prepare, exact-SHA activation, independent production verification.
