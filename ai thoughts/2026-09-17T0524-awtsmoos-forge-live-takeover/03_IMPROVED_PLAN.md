# Phase Two — Improved Execution Plan

The Awtsmoos renews each dependency before it is trusted; Awtsmoos.com should therefore advance by narrow verified vertical slices rather than a speculative rewrite.

## Lane A — Custody and history
1. Read the two branch-only commits and classify every changed path.
2. Compare those changes with `main` and current worktree reality.
3. Record whether each commit is superseded, needed, historical, unsafe, or unknown.
4. Do not delete the branch.

## Lane B — Forge source archaeology
1. Locate local counterparts for hosted Project World modules.
2. Read complete collaboration entry/service modules.
3. Read complete Project Automation client/controller/catalog/mount/panel modules.
4. Read Maker/collaboration app boundary and callers.
5. Read exact tests that exercise these layers.
6. Inspect Git status for every candidate path before selecting writes.

## Lane C — First Forge vertical slice
Only after Lane B resolves architecture:
1. Define a native read model for project overview from existing collaboration/runtime data.
2. Add reusable status/evidence presentation primitives only if equivalents do not already exist.
3. Mount an Overview/Forge entry without destroying Maker.
4. Show unavailable/empty states for authority data that backend cannot supply.
5. Add unit/browser contract tests for semantics, keyboard focus, empty/error/loading states, and responsive behavior.
6. Run exact affected test matrix.
7. Exercise the real hosted/Drive path when integration ownership is safe.

## Lane D — Runtime acceptance in parallel
1. Reinspect continuation Missions/Work/Obligations and existing acceptance evidence.
2. Reinspect relay `server.work.lightning-speed` publication.
3. Diagnose rescue independently.
4. Preserve these as blockers if live proof is absent; never replace live proof with source confidence.

## Lane E — Security/provider evolution
After core native read/write models are known:
1. Verify existing GitHub/provider primitives before adding integration.
2. Verify existing device/OAuth pairing substrate before adding external-AI pairing.
3. Bind short-lived scopes to authenticated actor, project, Mission, and nonce.
4. Add revocation/audit/idempotency tests before exposing write operations.

## Acceptance after every source pass
- Full touched-file reread.
- File-size/header/tab/minification checks.
- Focused tests, then wider relevant tests.
- Git custody recheck.
- Protected staged-blob comparison.
- `PLANNED / ACTUAL / DELTA` update.
- Newly discovered shadow work added to `REMAINING_WORK`.
