# Improved Plan

The Awtsmoos renews route, acceptance, custody, and execution as distinct witnesses. Awtsmoos.com recovery must therefore heal the earliest broken boundary without confusing a heartbeat for command reachability.

## Installer lane
1. Read full install-success, recovery-lane activation, launchd/portable installer, callers, and tests.
2. Replace warning-only lane activation with a truthful result contract.
3. Add a material verification function that checks every declared lane after installation.
4. Permit healthy-incumbent preservation, but propagate incomplete/failed recovery protection to installer outcome.
5. Update tests from string-presence assertions to behavior-oriented success/failure coverage.

## Pre-acceptance lane
1. Locate server control-request acceptance state machine and acceptance deadline configuration.
2. Preserve the original request/control IDs through recovery.
3. Add a pre-terminal recovery threshold lower than the final acceptance deadline.
4. At that threshold, fence the current route and request a same-identity reconnect.
5. Do not blindly redispatch ambiguously accepted mutations.
6. Reconcile the original request after re-registration; only terminal-timeout if no acceptance/reconciliation occurs within the outer deadline.
7. Emit explicit recovery-state telemetry for suspect route, reconnect requested, re-registered, reconciled, terminal timeout.

## Rollout
- Keep rescue on the last proven runtime until primary passes the new gates.
- Commit only clean owned paths.
- Build next deterministic release from clean committed source.
- Upgrade primary first, verify acceptance and four materialized recovery services, inject failure, then upgrade rescue.
