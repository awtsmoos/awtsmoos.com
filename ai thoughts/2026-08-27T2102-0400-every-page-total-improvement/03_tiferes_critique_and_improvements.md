# Tiferes — Critique Before the Universal Layer Manifests

Boruch Hashem. Blessed is He.

Tiferes joins the generosity of “improve everything” with the precision of “break nothing.” The Awtsmoos.com site becomes coherent not when every page looks identical, but when every page shares trustworthy foundations while preserving truthful purpose.

## Critique and improvements

1. “Every page” cannot mean identical visual skin; preserve application identity.
2. Begin from shared defects, not aesthetic taste.
3. Audit existing shared UI work before creating competing primitives.
4. Prefer route adapters over broad selectors.
5. Establish a route registry so audit coverage is explicit.
6. Include nested application entrypoints, not only top-level `geelooy/*/index.html`.
7. Classify pages by shell type: content, social, workspace, game, utility, migration/admin.
8. Give each shell type a density and navigation policy.
9. Treat 320px as a hard layout constraint.
10. Add vertical-height stress for games/studios with fixed controls.
11. Stress long text, URLs, filenames, aliases, errors, and localization.
12. Detect `100vw` overflow and fixed-position clipping.
13. Detect arbitrary z-index inflation.
14. Detect global element selectors in route-local CSS.
15. Detect missing focus-visible states.
16. Detect hover-only affordances.
17. Detect animation without reduced-motion alternative.
18. Detect destructive actions that look primary.
19. Detect simultaneous competing panels on narrow screens.
20. Detect nested card/border density like the original social screenshot.
21. Audit form field label/error/help relationships.
22. Audit modal/drawer focus trap/restoration.
23. Audit keyboard escape behavior.
24. Audit safe-area insets for bottom bars.
25. Audit browser console and network errors.
26. Measure request count and transfer bytes per representative route.
27. Compare compact and non-compact JS behavior, not only bytes.
28. Include dependency freshness in compact cache keys.
29. Verify generated compression validators and content-encoding negotiation.
30. Avoid loading non-critical advanced tools on first paint.
31. Defer/lazy-load page-specific heavy features where architecture supports it.
32. Keep initial HTML useful before optional enhancement scripts.
33. Check CSS import waterfall depth.
34. Consolidate only when equivalent behavior is proven.
35. Keep social composer clarity work compatible with Creator command-palette work.
36. Preserve Mitzvah World generated artifacts by regenerating from source.
37. Treat the five upstream commits as required input before final release.
38. Secret-scan the full candidate commit, including unrelated untracked files.
39. Review deleted files semantically; deletion may represent legitimate refactor or accidental loss.
40. Verify no detached worktree contains unique unpreserved commits before any cleanup.
41. Run targeted tests per family before broad release tests.
42. Use `scripts/bhRelease.mjs` only after reading its full release/git/deploy contracts.
43. Verify production checkout/release source matches pushed commit.
44. Verify public HTTP and browser result after deployment.
45. Re-run route audit against production to catch cache/deploy-only failures.
