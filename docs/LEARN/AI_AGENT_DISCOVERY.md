# AI Agent Discovery

## Goal

Find the right files quickly without treating semantic search, generated evidence, or repository size as authority.

## Recommended order

1. `llms.txt` for compact navigation.
2. `docs/README.md` or `/docs/` for human framing.
3. `docs/LEARN/` when the task needs conceptual context.
4. `docs/AI/MANIFEST.json` for project discovery.
5. `docs/AI/API_TUTORIALS/MANIFEST.json` for route teaching/discovery.
6. Generated evidence for exhaustive lists.
7. Current source and tests for final authority.

## Route packet

Each AI tutorial record includes stable ID, route, source, family/manual, derech health, dynamic parameters, source-level method/vessel/status/header evidence, selected callers/tests, starter example only when method evidence exists, and related routes.

## Evidence rules

- unknown method is unknown;
- caller match is navigation evidence, not runtime proof;
- lexical statuses/headers are not exhaustive runtime schemas;
- failed derech syntax weakens runtime confidence;
- generated family/test matching can be heuristic;
- source/test evidence wins when stale docs disagree.

## Efficient question

Concept → human tutorial → route/project record → source → related callers/tests → runtime verification.
