# WebSockets 101

## What you will learn

How Awtsmoos realtime behavior differs from HTTP route tutorials.

## Platform

The dynamic server owns a realtime platform with an application registry and application router. Current generated evidence records eight versioned realtime applications plus production event/message literals.

## Major examples

- Awtsmoos core/social;
- Sefira Clash;
- Mitzvah World;
- Ohr HaGnuz;
- Scribe Journey;
- Tunnel Activity;
- Shema Strike.

Mission Rooms and Tunnel Relay also have specialized admission/transport logic.

## Trust boundary

Realtime code trusts server-derived client identity, not identity claims inside an arbitrary message payload.

Mission Room admission additionally verifies WebSocket key, trusted account identity, canonical Origin, one-time ticket, current mission authorization, matching authority, and protocol version before accepting the handshake.
