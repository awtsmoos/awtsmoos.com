# Awtsmoos.com Project Guide

A project boundary is a practical unit for navigation, documentation, dependency evidence, and testing—not a promise that the runtime is isolated at that directory.

## Interactive Project Explorer

Open `/docs/?view=projects` to browse every current project boundary. The explorer can filter by exact generated type, public-entry evidence, test-file evidence, documentation coverage, and text across paths, entries, public URLs, and dependency names.

Selecting a project reveals:

- exact path/type/family;
- file-category shape;
- source entry files;
- public HTML entry evidence;
- lexical symbol summary;
- incoming/outgoing project dependency evidence;
- external package evidence;
- test-file evidence;
- local/central human documentation;
- generated project tutorial;
- project-aware Ask and copyable project path.

## Generated project teaching

[Project Tutorial Index](../GENERATED/PROJECT_TUTORIAL_INDEX.md) gives one generated tutorial for every current project boundary. [Project Type Summary](../GENERATED/PROJECT_TYPE_SUMMARY.md) summarizes the current type census without freezing counts into this manual.

Each generated tutorial is evidence, not architecture law: imports are lexical, public entries are discovered `index.html` files, symbols are lexical summaries, and test-file counts are not behavioral-coverage scores.

Human family/system manual → generated project tutorial → dependency/public-entry/symbol evidence → exact source/tests → runtime verification.
