# AI Discovery Guide

Use human meaning first, bounded machine evidence second, then current source/tests/runtime.

## Navigation order

1. `llms.txt`.
2. `docs/README.md` or `/docs/`.
3. `docs/LEARN/` for unfamiliar concepts.
4. nearest human API/project/system manual.
5. `docs/AI/MANIFEST.json` for project discovery.
6. `docs/AI/SYSTEMS/MANIFEST.json` for Data/Security/Realtime system discovery.
7. `docs/AI/API_TUTORIALS/MANIFEST.json` for routes.
8. generated evidence.
9. exact current source/tests/runtime.

## System packets

`docs/AI/SYSTEMS/RECORDS/` contains one bounded packet per curated stable system. Packets include human manuals, verified project/source anchors, generated evidence, claims boundary, change risk, environment-name evidence, realtime application registrations, and lexical event evidence where relevant.

Environment packets contain **names only**. Event strings are not protocol schemas. Security packets are not audit findings. Data packets do not invent durability/consistency guarantees.

## Browser discovery

- Learn: `/docs/?view=learn`
- API: `/docs/?view=api`
- Projects: `/docs/?view=projects`
- Systems: `/docs/?view=systems`

## Evidence rules

Unknown API method remains unknown. Project imports are lexical. Environment values are never published. Authentication does not imply authorization. Public entry/source registration does not imply runtime health. Current source/tests win when documentation conflicts.
