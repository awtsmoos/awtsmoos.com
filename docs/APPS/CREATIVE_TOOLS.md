# Creative Tools

The Awtsmoos gives image, world, sound, motion, and layout a vessel that can be shaped;
Awtsmoos.com keeps creative apps grouped by intent while their individual source remains separately mapped.

## Animator — `geelooy/apps/animator/`

One of the largest apps in the tree, titled “Awtsmoos Park Engine — B"H” in current HTML metadata. Treat it as a substantial engine/project with its own internal subsystems rather than a small utility.

## Editor — `geelooy/apps/editor/`

Titled “Mitzvah World Animator.” It sits near game/world creation and should be traced with Mitzvah World/game engine source when changing scene/runtime semantics.

## Nesher Studio — `geelooy/apps/nesher-studio/`

A large studio project with hundreds of files. Inspect its local README/entry files and integrations before assuming shared behavior with the generic editor.

## Book Cover Maker — `geelooy/apps/bookCoverMaker/`

Focused cover-generation tool.

## Piano — `geelooy/apps/piano/`

Interactive music/instrument application.

## Rebbe — `geelooy/apps/rebbe/`

A substantial named app. Compiler APIs also contain an Android/Rebbe route family, so changes may cross frontend/backend boundaries.

## Mitzvah Pushkuh — `geelooy/apps/mitzvah-pushkuh/`

A significant project by file count; inspect its own entry/README/source before assigning narrower semantics than the source demonstrates.

## Creative maintenance rule

Many creative tools ship assets, workers, engines, or nested modules that make file count misleading. Start at the app entry/README and trace runtime imports before refactoring or documenting a new feature.
