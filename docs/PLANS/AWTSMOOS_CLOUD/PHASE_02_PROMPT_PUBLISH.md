# Phase 02 — One Prompt to a Production Website or App

## Product promise

A signed-in user can tell ChatGPT/Awtsmoos what they want. The system creates a durable project, generates source into an isolated preview, provisions requested bounded capabilities, shows evidence, and publishes an immutable production revision only through the deployment layer.

## Canonical flow

1. Resolve signed-in account and chosen alias.
2. Convert prompt into a bounded project specification.
3. Create/reconcile project identity idempotently.
4. Generate files into preview/workspace source.
5. Validate source, routes, accessibility basics, and project limits.
6. Provision requested DB/auth/storage/function/secret bindings through explicit APIs.
7. Produce preview URL and generation testimony.
8. User or authorized agent explicitly publishes.
9. Create immutable deployment and verify health.
10. Optionally connect/verify/activate custom domain.
11. Persist activity history so later prompts continue the same project.

## Prompt specification must be explicit

The prompt compiler should emit project name/slug, site type, pages, content goals, visual direction, required forms/data, requested integrations, runtime class, storage needs, authentication needs, custom-domain intent, and estimated paid server capabilities. It must not silently invent unrestricted infrastructure authority.

## Business archetypes

Ship complete production archetypes, not cosmetic themes: contractor lead site, restaurant/menu/catering, creator/media, synagogue/events/donations/zmanim, consultant/booking/intake, and store/catalog/orders. Each archetype should include a useful data model and operational workflow.

## Import/export

Existing ZIP, HTML, or Git projects reconcile into the same project/deployment model. Every project must remain exportable with source and user-owned data so Awtsmoos earns retention through usefulness rather than lock-in.

## Acceptance gate

A fresh account can create a real site from one prompt, receive a preview, publish revision 1, change the site through a second prompt, preview revision 2, publish it, roll back to revision 1, and connect a custom domain without manually editing infrastructure configuration.
