# Phase 04 — Geelooy OS and Tunnel Control Plane

Geelooy OS is the advanced cloud console while the prompt interface remains the simple doorway. Complexity is available, never required.

## Existing foundation

- All 80 canonical apps/games are represented in the OS launcher.
- Native integrations are preferred where available; remaining products use supervised same-origin hosting.
- Browser Tunnel has authenticated session-bound account actions.
- Account graph already projects aliases, heichelos, series, posts, Docs, and applications.

## Next graph objects

Add first-class project, deployment, domain, database, function, secret, queue/job, runtime/service, backup, alert, usage, and billing-plan objects. Their IDs must remain stable across refreshes.

## Native management windows

Sites, Projects, Deployments, Domains, Databases, Functions, Jobs, Storage, Compute, Logs, Metrics, Secrets, Wallet/Usage, and Permissions should each have focused native OS surfaces rather than one giant console.

## Universal workflows

Implement Open With / Send To, shared projects/assets, global background jobs, command palette/search, recent/pinned work, cross-device continuation, permissions inspector, and audit timeline. A project output should move between Studio, Docs, media tools, social tools, games, storage, and hosting without repeated download/upload cycles.

## Tunnel authority

Tunnel may operate broadly across the signed-in account, but authority always comes from normal account/project capabilities. Never export browser cookies or allow caller-supplied user IDs to replace session identity. Connected machines become explicit compute/storage/provider resources with scoped permissions and audit.

## Completion test

From Geelooy OS, a user can inspect one project, open source, view deployment history, roll back, inspect DB/functions/jobs/logs, connect a domain, see usage, and ask ChatGPT to perform the same operations through explicit APIs. Mobile and keyboard operation must remain practical.
