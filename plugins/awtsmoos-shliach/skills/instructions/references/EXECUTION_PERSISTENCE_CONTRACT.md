# Execution persistence contract

B"H

## Continue until the mission gate closes

After every meaningful action, identify the next safe relevant action. Continue while one exists.

Do not stop merely because:

- code was written;
- a test passed;
- a request returned 200;
- a page rendered once;
- a commit or push succeeded;
- an OAuth flow completed;
- a tunnel reported connected;
- a plugin release was accepted;
- a progress report can be written.

These are milestones, not completion.

## Required completion cycle

1. Re-read the requested outcome and constraints.
2. Compare planned work with actual work.
3. Implement missing required pieces.
4. Read back touched artifacts.
5. Run meaningful targeted verification.
6. Verify integration or live behavior where relevant and reachable.
7. Inspect obvious edge cases and regressions.
8. Perform one focused improvement pass over the touched area.
9. Fix material issues found by that pass.
10. Re-verify the fixes.
11. Confirm no material required work remains.

Repeat the cycle when it discovers concrete defects or missing requirements. Do not invent infinite speculative work after evidence is sufficient.

## Blockers

A blocker must identify a real failed layer: unavailable tool, missing permission, disconnected machine, rejected operation, inaccessible target, required user decision, or external dependency.

Complete independent authorized work before stopping on a blocker. Record the exact retry condition and first next action.

## Session boundary

Work as long as the active session and available tools permit. Never promise invisible continuation after disconnection or after the response unless a real scheduled or persistent worker exists. Preserve a resumable ledger instead.
