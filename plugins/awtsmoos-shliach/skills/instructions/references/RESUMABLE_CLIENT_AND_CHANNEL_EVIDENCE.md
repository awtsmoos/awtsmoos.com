# Resume and verify the Awtsmoos tunnel

Discover the current action schemas and instruction generation before using any
operation below. Keep the immutable authorized device route, root, ownership and
granted scopes bound to the work. The Awtsmoos narrative accompanies the evidence;
never turn a waiting receipt into a claim that execution succeeded.

## Preserve one execution

Save the original controlRequestId, clientRequestId, nonce, traceId, owner and
requested action before dispatch. Save the complete observeWith or retryPayload
receipt before waiting. Pending means observe the existing request using
retryAction with its complete identity, including requestedAction. A pending
commandWait is itself an observation receipt; reconcile it rather than issue
replacement waits repeatedly. Never pull job IDs or output from a mismatched
response's diagnostic body.

A commandRun may finish inline with stdout, stderr and integer exitCode, including
empty successful output. Otherwise preserve jobId and ownership, observe terminal
status, and read both streams through advancing output cursors. Early stdout is
not success. Record nonzero exit status and partial/unavailable output honestly.

Use the repository's scripts/tunnel/reliableCommandClient.cjs for separately
authorized Node clients. Set AWTSMOOS_COMMAND_CHECKPOINT to a private per-command
path outside Git; supply the same endpoint, command and cwd when resuming.
The journal binds those inputs, admits one living owner, saves atomically and
keeps bounded redacted trace events. A lost dispatch reply resumes by observing
the saved identity, never submitting a replacement command. Corrupt checkpoints
block; they never silently reset. A completed checkpoint returns its recorded
result. Inspect the current script and guide before relying on platform-specific
behavior. Tokens stay outside source, URLs, trace logs and handoffs.

## Diagnose channel health separately

Use tunnelConnectionDiagnostics for retained connection transitions and
tunnelWorkHealth for process, relay, repository and explicitly unverified checks.
Then perform only task-relevant authorized probes: harmless owned command with
exact expected stdout and exit code; temporary scoped file write/read/hash/cleanup;
browser capture and real image inspection when UI work is involved. An installed
Mac localhost test is distinct from an authenticated external relay or MCP test.
Report each boundary and timestamps separately.

Carry one traceId through ingress, command receipt and follow-up observations.
Capture request/control/job IDs, requested action, receipt state, deviceAccepted,
progressPhase, timestamps and current generation when returned. Never log
credentials, unrestricted request bodies, private file contents or commands in
shared diagnostics. Compare client trace events with action history/stream and
connection diagnostics discovered through their current schemas. Missing
acceptance evidence is not proof of command failure or permission to resend.

## Keep bounded parallel work responsive

Use existing reserved lanes and per-owner queues. Begin with a small measured
bound, leave health/status/cancellation capacity, serialize same-path writes and
same-conversation browser sends, and reduce admission after overload. Preserve
retry timing and receipts instead of polling tightly. Measure p50/p95 and failures
at the actual authorized external route; local speed alone does not prove
Internet performance. Do not create competing schedulers or watchdogs.

## Preserve accepted work during upgrades

Use the canonical candidate/promote and deployment process, retaining immutable
device identity and the last working runtime. Prove candidate registration and
actual command capability before promotion; retain owner fencing and recovery
evidence. Do not kill the live runtime for a test while other workers are using it.
Test process death, reconnect, duplicate delivery, cancellation and corrupted
state in isolated fixtures first. A harness simulation is not a live restart.
After activation separately verify running version, public release and an
authenticated intended-client operation.

## Checkpoint work and enforce frontend evidence

Begin or resume the existing tunnelWork record and plan. Record completed checks,
remaining work, exact source/release, pending receipts, retry budget, blockers and
next authorized action using the current revision. Fetch and read injected
instructions, then acknowledge only their exact hash. Refresh after scope,
generation or source changes. Resolve revision conflicts before updating.

For frontend work read CSS_AND_EXTERNAL_VISUAL_VERIFICATION.md. Fix the owning
cascade, run real width/interaction/computed-style checks, transfer every required
screenshot with exact byte/hash verification, and inspect the images with the
agent host's image tools. Use explicit passed/failed/blocked reviewVerdict.
Work/release gates must remain blocked for unresolved CSS, stale source, missing
images or unverified review. Instructions cannot guarantee an agent obeys;
runtime gates enforce the checks they can actually verify.

Continue independent authorized work and give factual updates at least once per
minute. Save a handoff before stopping. Durable jobs may survive a chat turn;
these skills do not extend the host's turn lifetime or authorize new providers,
unbounded costs, indefinite browser prompting or expanded account access.
