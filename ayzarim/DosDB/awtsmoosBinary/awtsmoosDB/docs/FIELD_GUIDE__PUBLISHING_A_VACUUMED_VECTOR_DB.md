# Field Guide: Publishing a Vacuumed Vector DB

## Candidate court

- Candidate path is outside the live RAG root.
- Source and rollback are preserved.
- Record count and semantic digest match.
- Canonical vector corpus is unchanged.
- List, dimensions, metric, registry, entry node, keys, nodes, payloads, and allocations pass.
- Deterministic self-vector and sampled recall pass.
- Read-only reopen changes no bytes.
- Candidate SHA-256 is recorded.

## API court

Generate a complete fast manifest, publish only into an isolated root, start port 8081, and run the full matrix on both strict route spellings. Record cold and warm timing, stop, prove port closure, restart, and repeat.

## Approval gate

Prepare exact cutover and rollback commands but do not execute them until the user explicitly authorizes production replacement/restart. Preserve the production PID and port otherwise.

## After approved cutover

Recompute live hash, re-run all published lanes, verify rollback, and retain source clone, candidate, vectors, manifests, and evidence.
