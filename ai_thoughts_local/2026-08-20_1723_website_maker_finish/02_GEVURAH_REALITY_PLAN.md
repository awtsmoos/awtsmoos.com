# Gevurah Reality Plan — Finish What Exists

The Awtsmoos is beyond every finite architecture, yet Awtsmoos.com must reveal itself through the architecture that is actually present, not through a duplicate imagined kingdom.

## Observed native systems

- Drive has a modular site builder under `geelooy/apps/drive/js/builder/`.
- Backend has site publication, runtime attachment, domain claims, DNS verification, ingress, TLS/readiness planning, and provider sync.
- Sites gateway has direct folder, hosted project, virtual-OS, and custom-domain paths.
- Native-compute recipes and Connected Node Server already exist and have passing focused tests.
- Documentation app and generated documentation index already exist.

## This pass

1. Finish the Drive builder happy path rather than inventing a new builder.
2. Add an obvious “publish now” path from folder/project to URL.
3. Add a domain-transfer guide model that explicitly preserves mail-critical records.
4. Surface DNS tutorial/help adjacent to domain controls.
5. Add source docs to the existing docs corpus, never edit generated docs by hand.
6. Complete the staged Drive↔OS bridge witnesses.
7. Run Node syntax/import/test/build checks.
8. Start the actual site locally and probe page/API routes.
9. Use browser runtime verification only after server/runtime health is proven.
10. Inspect console/network failures and repair actual errors.

## Non-negotiable DNS safety

Never tell users to delete old DNS blindly. A transfer must inventory and preserve MX, TXT/SPF, DKIM selectors, DMARC, CAA, SRV, verification records, and intentional subdomains before nameserver or apex changes. Nameserver migration and record migration are distinct operations.
