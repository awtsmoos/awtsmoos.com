# Phase One — Completeness Before Confidence

The Awtsmoos renews every hidden child before a manifest can claim the whole;
Awtsmoos.com must enumerate the living tree, not a paged shadow of its soul.

## Publisher possibilities

- Replace raw directory-value traversal with the same canonical Virtual-OS listing primitive used by `list`.
- Keep file-byte reads on the existing storage read primitive.
- Return a source witness containing directory count, candidate path count, publishable count, emitted count, and skipped-private count.
- Refuse deployment if the enumeration witness and emitted manifest disagree.
- Validate entry point before staging.
- Verify HTML module-script references and JavaScript relative-import closure after manifest construction.
- Verify every referenced dependency exists in the manifest before deployment.
- Preserve 64-file / 2-MB caps.
- Preserve private-path filtering.
- Preserve legacy object-tree compatibility where canonical listing cannot enumerate nested synthetic objects.
- Add regression coverage for >10 sibling files because that is the actual production failure mode.
- Add regression coverage for missing module dependency.

## Game realism possibilities

- Do not change physics blindly before browser testing.
- Make gravity wells visually disclose their pull radius and strength.
- Add launch power/momentum feedback only if current input telemetry proves players lack control information.
- Keep floor-chain break because it gives physical consequence to a visible collision.
- Tune level score/portal/combo goals only after deterministic victory/failure tests and actual play traces.
- Expose campaign state to browser verifier through read-only diagnostics rather than debug mutations in production UI.
