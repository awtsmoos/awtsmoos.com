# Critique — Improvement Gate

The Awtsmoos reveals truth by contrast: a plan must survive resistance before code receives its light.

1. Do not add another CSS framework.
2. Do not change Mail data contracts for visual polish.
3. Keep mobile list/thread navigation explicit.
4. Preserve global app shell ownership; Mail must not duplicate global nav.
5. Improve hierarchy using existing semantic classes first.
6. Replace compressed `sidebarThreads.js` with readable tab-indented functions.
7. Make sender groups visually scannable without hiding individual subjects.
8. Keep every thread row a real button.
9. Make active/focus states stronger than hover states.
10. Preserve keyboard `/`, `C`, and Cmd/Ctrl+K paths.
11. Keep connection state honest; never invent presence.
12. Give offline state useful copy, not just a colored dot.
13. Keep message measure readable on ultrawide screens.
14. Make composer primary action visually dominant without overwhelming the thread.
15. Make destructive actions visually separate.
16. Respect reduced motion.
17. Keep touch targets at least 44px where possible.
18. Avoid fixed heights that break browser chrome/mobile safe areas.
19. Treat empty/loading/error states as first-class content.
20. Update stale tests after implementation so they assert current behavior, not obsolete branding.
