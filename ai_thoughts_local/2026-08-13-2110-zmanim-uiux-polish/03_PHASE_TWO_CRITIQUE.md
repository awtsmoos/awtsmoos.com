# Phase Two — Critique and 24 Improvements

The Awtsmoos renews the plan before the plan can harden into habit;
Awtsmoos.com lets critique remove ornament where clarity should inhabit.

1. The full calendar should not be visible by default on mobile; it consumes too much first-screen space.
2. The hero headline is aesthetically pleasant but too tall for a utility page used daily.
3. Three large shita cards are educational but too expensive above the fold.
4. A compact segmented shita control can preserve one-tap switching while methodology holds descriptions.
5. Search should become a persistent "place" control rather than a form-like block.
6. Recent places are valuable, but adding favorites and geolocation simultaneously risks feature sprawl; start with recent places only.
7. Browser geolocation requires permission UX and should remain optional future work unless clearly valuable after visual testing.
8. Manual coordinates should remain API/advanced territory for now.
9. The next-zman hero should include previous/next context rather than a generic explanatory sentence.
10. A dedicated key-times component is more useful than trying to make all 18 cards equally compact.
11. The all-zmanim section should use row-like cards with label/time aligned for scanning.
12. Notes should be visually secondary and possibly hidden behind a details affordance on narrow screens.
13. Status labels should be sparse; repeated "Upcoming" chips add noise.
14. Only "Next", "Passed" through opacity, and "Unavailable" need visible treatment.
15. Timeline marker needs a real dot/position indicator in addition to fill percentage.
16. The selected date should be a proper button that opens the calendar, with civil and Hebrew date together.
17. The page needs a stable section title before the full list: "All zmanim" plus a short method label.
18. Share controls should sit near the selected-date/location context but not interrupt the dashboard.
19. USNO status and safety warning should become a compact trust panel, still legible and not hidden.
20. API links belong in resources/footer, not the hero top line.
21. Desktop should use a left control column and right daily dashboard only when width genuinely supports it; otherwise vertical stacking is clearer.
22. Sticky mobile context should activate only after the main next-zman card scrolls away and must not obscure content.
23. Avoid adding icons that require libraries; use simple inline SVG or text glyphs only if they improve recognition.
24. The visual system needs fewer radii and less shadow to feel more premium and less card-heavy.

## Revised direction
The second-pass concept becomes: compact brand header, one control bar (place/date/shita), one strong next-zman surface, one six-item key-times strip, one improved timeline, then a dense all-zmanim section. Calendar, methodology, sharing, and trust details remain available but no longer dominate the first screen. Recent places are the one new convenience feature promoted from brainstorm because it materially reduces repeated search friction without permission prompts.
