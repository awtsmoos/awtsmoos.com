# Agent Site + Git Fabric — Broad Possibility Map

This document is an implementation design ledger, not hidden reasoning.

## North Star

A signed-in Awtsmoos user should be able to open any Awtsmoos Shliach chat and say: create/open this website. The agent should discover an authorized project, edit files through a bounded project handle, return a server-issued preview URL, publish to a stable live URL, manage custom-domain evidence, and optionally commit/push the resulting revision.

## Product surfaces

- Agent project handles independent of filesystem paths.
- Native-tunnel and Virtual-OS workspace backends behind one project API.
- Server-issued preview and live URLs for every deployable website.
- Domain provider connections with server-held secrets and zone-scoped permissions.
- DNS change planning, diff, apply, verify, rollback, and audit testimony.
- Repository history independent of GitHub.
- Optional GitHub connection through OAuth/GitHub App before any manual key workflow.
- Optional SSH/HTTPS credentials stored server-side, never exposed to browser JavaScript.
- Awtsmoos Repository as first-party revision/branch/diff service.
- Future Git Smart HTTP/SSH compatibility so ordinary git can clone/fetch/push to a Virtual OS repository.
- Repository-to-site deployments comparable to Pages, but with preview generations, custom domains, server functions only when an isolation tier exists, and peruta/usage testimony.
- One project activity ledger linking agent edits, deploys, DNS changes, commits, pushes, and domain state.

## Important invariants

- Hostname never becomes a filesystem path.
- Agent session never receives provider secrets.
- Git remote credentials never live in page-local storage.
- Project capability is narrower than account authority and expires.
- Preview URL is generated by the server and tied to an immutable generation.
- Live URL is generated from actual publish/domain state, never guessed by a client.
- DNS mutations are planned and validated before provider apply.
- Git commit and Git push are separate operations with separate evidence.
- Virtual OS repository hosting must work without GitHub.
- External GitHub remains an adapter, not the source of truth for Awtsmoos projects.

## Extra expansion ideas

- One-click fork of any authorized site into a new project.
- Branch preview URLs for every repository branch or revision.
- Deploy-from-commit and rollback-to-commit.
- Signed deployment manifests connecting commit hash to deployed generation.
- Provider-neutral DNS connectors: Cloudflare, Route 53, registrar APIs, future RFC2136 where appropriate.
- Agent-visible dry-run DNS change sets before apply.
- Repository code search, blame, diff, commit graph, tags, releases, issue-like project notes, and deployment checks.
- First-party artifact registry for static assets and future functions.
- Project templates and instant site bootstrap by an agent.
- Cross-session handoff links that identify project, preview generation, and repository revision without exposing secrets.
- Public or private repository visibility independent from site visibility.
- Signed webhooks/events for external CI while retaining first-party deploy pipelines.
