# Phase Three — 36 Final Improvements

> The first plan saw possibility. The second plan saw boundaries. The third sees consequence: every click should tell the truth before and after it changes reality.

1. Read-only operation policy is explicit, immutable, importable, testable.
2. Mutation policy is explicit, immutable, importable, testable.
3. Unknown operation keys default to non-bulk execution rather than silently becoming readable.
4. `allKeys()` returns reads only.
5. `groupKeys()` returns reads only for any mixed group.
6. A separate `mutationKeys()` exists for explicit action rendering.
7. Follow cannot be triggered by Explore All.
8. Notify cannot be triggered by Explore All.
9. Live subscribe cannot be triggered by Explore All.
10. Presence POST cannot be triggered by Explore All.
11. Live publish cannot be triggered by Explore All.
12. Mutation controls display a side-effect badge.
13. Mutation controls use verbs that match the operation.
14. Mutation controls are not styled like passive exploration.
15. Each mutation exposes consequence copy sourced from policy metadata.
16. Each mutation preserves existing argument requirements.
17. Read cards expose a digest before raw response.
18. Digest handles arrays, objects, strings, null, booleans, and errors.
19. Digest never invents entity names absent from response.
20. Raw JSON sits in native details with copy/debug utility preserved if existing architecture supports it.
21. Failed reads render Retry for the same key only.
22. Failed mutations preserve the trigger and input state.
23. Page boot shell names the route’s real capabilities.
24. Page boot shell links to human social destinations before runtime.
25. Page boot shell has a noscript recovery state.
26. Page boot shell does not fake live data.
27. Social style gateway imports new safety/result modules rather than inflating old files.
28. Review consequence helper maps only allowed action names currently present in source.
29. Review action grouping distinguishes organizational vs publication/destructive decisions.
30. Review consequence text mentions schedule timestamp only when relevant field exists.
31. Review retains raw payload/history auditability.
32. Mission event discovery searches producers before UI filter mutation.
33. Series structural discovery traces endpoints, editor, order state, and tests before writing.
34. Every touched/new source file remains under 120 lines.
35. Tests include a mutation-leak sentinel that fails if bulk plans contain POST keys.
36. Browser verification explicitly checks slow/preboot Social, read-all safety, raw-response disclosure, mutation affordances, review consequences, and mobile layout.

## Final revelation
The most important UI change is not prettier CSS. It is making the moral topology of the application visible: seeing is not acting; inspecting is not publishing; exploring is not following; reviewing is not judging until the person deliberately crosses that boundary.
