# Phase Two — 28 Improvements After Critique

> Chesed imagined infinite capability. Gevurah now demands that power become safe, bounded, and comprehensible. The Awtsmoos contains both without contradiction.

1. Classify every Social operation as read or mutation in one immutable source of truth.
2. Never infer mutation status from button label text.
3. Make bulk/group plan expansion read-only by construction.
4. Keep mutation keys completely outside `allKeys()`.
5. Require explicit individual activation for every POST operation.
6. Give each mutation a consequence sentence before activation.
7. Give each mutation a working state and disable only that trigger while pending.
8. Preserve API signatures; safety belongs in planning/rendering orchestration.
9. Do not hide developer JSON; demote it beneath a human digest.
10. Digest arrays as counts + representative identity, not `[object Object]`.
11. Digest objects using known fields only; do not hallucinate labels.
12. Keep exact status/body under native `details` for auditability.
13. Make Run panel language say “Explore panel” or equivalent when read-only.
14. Make Run all language say “Explore all read-only panels.”
15. Prevent socket/live mutation functions from being invoked by read exploration.
16. Static Social shell should explain Overview/Live/Search/Feed/Graph before JS boots.
17. Static shell should link to Social Hub, Mail, Signals, and Heichelos as recovery/destination choices.
18. Add a no-JS explanation rather than leaving a dead loading message.
19. Preserve semantic page title/description and shared shell boot.
20. Do not invent mission event types; discover producer strings first.
21. If mission enum remains distributed, group mission-prefixed signals client-side rather than guessing a filter query.
22. Review decision actions need consequence text derived only from legal action names and current state.
23. Publish/reject/schedule receive stronger visual grouping than assign/triage.
24. Raw review payload stays secondary because current `ReviewDetail` already has semantic summary.
25. Decision note remains preserved and visible near consequence language.
26. Series policy in Review is governance, not series structure editing; do not conflate them.
27. Search for actual reorder/edit endpoints before any series mutation UI.
28. Verification must prove mutation safety with tests that fail if POST keys leak into bulk plans.

## Risk graph
- Misclassified mutation → unintended side effect → central immutable policy + tests.
- Human digest hides evidence → debugging loss → raw response remains accessible.
- Static shell duplicates dynamic app → drift → static shell stays explanatory, not data-driven.
- Review consequence copy overpromises → legal confusion → use only current action/state semantics.
- Mission guessed type → empty/broken filters → source-proven enum only.
