2. Keep intent and attachment arrays structurally distinct.
3. Add provider-specific failure reasons.
4. Make stale evidence visibly stale.
5. Never serialize provider secret values.
6. Resolve binding names to presence only.
7. Distinguish missing, configured, degraded, and ready.
8. Include last-observed timestamps.
9. Include evidence source identity.
10. Confine Git paths beneath project roots.
11. Avoid shell interpolation for Git arguments.
12. Prefer spawn/execFile argument arrays.
13. Report detached HEAD explicitly.
14. Report dirty worktree explicitly.
15. Report ahead/behind when upstream exists.
16. Do not auto-push.
17. Do not auto-pull across conflicts.
18. Keep destructive Git actions absent initially.
19. Prove Social permissions through existing authorization APIs.
20. Distinguish alias existence from write authority.
21. Let domains expose the next actionable verification step.
22. Keep TLS state separate from DNS ownership.
23. Add binding readiness without values.
24. Keep runtime metrics bounded and sampled.
25. Use one Project Testimony shape everywhere.
26. Add contract tests before browser polish.
27. Re-read every rewritten file after writes.
28. Run focused tests, then full suites.
29. Enforce the 120-line ceiling mechanically.
30. Browser-test desktop and narrow viewport before declaring UX complete.
31. Preserve existing unrelated workers and files.
32. Record unknowns instead of inventing support.
33. Make provider actionability explicit: attach, verify, repair, detach.
34. Keep server testimony authoritative over browser-local inference.
35. Make every provider attachment traceable to evidence.
