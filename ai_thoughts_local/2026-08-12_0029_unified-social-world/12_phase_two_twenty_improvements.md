# Phase Two — Twenty-Four Improvements To The First Plan

The Awtsmoos renews the plan as surely as the world; Awtsmoos.com must let every critique become a clearer vessel, not a decorative word.

1. Do not touch the physical realtime transport; observed singleton architecture already satisfies the one-socket invariant.
2. Reuse universal chat `SEARCH` privately for related Torah instead of creating a new raw-RAG browser endpoint.
3. Never call universal chat `PUBLISH` from reading intelligence; publication remains an explicit user selection flow.
4. Treat the current recommendation endpoint as a public candidate generator only, because it does not know the private meaningful ledger.
5. Build personalized ranking from owner-authorized activity plus public candidates, preferably in-browser so private interests do not leave the user boundary.
6. Add Activity as a first-class app section backed by the existing private ledger rather than inventing another history store.
7. Add Discover as a first-class app section with explanation metadata and graceful sparse-candidate states.
8. Defer durable universal Saved until a real canonical storage owner is found or implemented; do not fake a universal bookmark backend.
9. Surface presence in the flagship using the existing trusted presence projection rather than querying socket/account internals.
10. Change anonymous hide preference to session scope while keeping authenticated server persistence authoritative.
11. Add an identity/status card that distinguishes signed-in alias, Ploni, hidden state, and reconnect state without exposing account ids.
12. Add local cross-section search over authorized summaries/metadata before attempting server body search; label the scope accurately.
13. Add private older-history loading using the observed `beforeSequence` seam and preserve scroll position when prepending.
14. Keep Mail reference-only and improve the visual bridge rather than duplicating bodies.
15. Keep group/admin actions delegated to existing private server authorization; UI only projects capabilities.
16. Related-comment intelligence should require sustained visibility plus substantial English text, not mere intersection.
17. Bound semantic comment/post excerpts before they become private search prompts.
18. Cache related-Torah results by bounded context fingerprint in session memory so revisiting does not repeat RAG work.
19. Track only source-card opens as new recommendation activity; do not record the generated private query body.
20. Render all returned source data with `textContent` and safe links; no search-result `innerHTML`.
21. Remove the existing comment-card alias `innerHTML` interpolation if `discussion.js` is rewritten, because safe text nodes cost little and reduce XSS surface.
22. Keep every new app responsibility in a small module so current near-ceiling controllers do not exceed 120 lines.
23. Add dedicated CSS modules for workspace header/search, activity/discovery, and reading intelligence rather than growing `components.css` or `layout.css` past their ceilings.
24. Test browser geometry through DOM measurements at all requested widths, not screenshot impressions.
