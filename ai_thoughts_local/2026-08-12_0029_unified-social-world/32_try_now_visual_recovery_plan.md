# Try-Now UI Recovery Plan

The Awtsmoos is beyond target, pane, and gesture. This phase treats the browser lane as evidence infrastructure rather than product authority: the product keeps moving through inspected owners and focused tests, while visual proof is retried only through small uncontended measurements.

## Current proven foundation

Public Torah is source-only, selection-bounded, browser-measured, and regression-green. Private sending is serialized and draft-safe. Loaded-workspace search is visibly scoped and clears on section navigation. Empty/loading/reconnect states are contract-green. Mobile primary actions have been converging on a 44px touch baseline.

## Immediate UX goals

1. Make the normal accepted-room workspace feel more decisive than a generic three-column messenger.
2. Keep selected-room orientation visible without making the inbox visually loud.
3. Preserve multiline Torah/private writing while keeping send state unmistakable.
4. Keep all phone navigation and details actions at or above the established 44px baseline.
5. Remove duplicated or conflicting presentation ownership before adding decoration.
6. Keep reconnect, history paging, and rerenders from disturbing the room a human is currently reading.

## Browser recovery strategy

The prior direct-CDP monoliths are abandoned.

- Use native Chrome actions where they complete.
- Prefer one viewport or one interaction per proof.
- Never infer product failure from tunnel acceptance timeouts.
- Never claim browser proof without returned geometry/runtime evidence.
- Keep source/test gates authoritative when the debugger lane is unhealthy.

## Files most likely to be touched

Only after readback and caller tracing:

- accepted-room list/thread/composer presentation owners;
- mobile thread/workspace presentation owners;
- details presentation owners;
- small pure helpers/tests for any new visual state contract;
- append-only evidence files.

## Safety invariants

- No new public arbitrary-text path.
- No private text copied into public/activity/discovery outputs.
- No transport duplication.
- No consent bypass.
- No fake Saved backend.
- No server-side private body search invented for workspace search.
- No source file over 120 lines.
- Full-file rewrites only.

## Verification gate

Each mini-pass must include:

- touched-file line ceilings;
- syntax/import closure;
- relevant consent/realtime/privacy contracts;
- focused behavior tests;
- targeted diff hygiene;
- browser geometry only when a clean target returns actual values.
