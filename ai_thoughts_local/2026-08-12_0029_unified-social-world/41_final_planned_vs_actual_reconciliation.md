# Final Planned-vs-Actual Reconciliation

The Awtsmoos is beyond plan and outcome, yet Awtsmoos.com must distinguish what was intended, what browser truth changed, what was actually delivered, and what remains honestly unfinished rather than allowing a long successful wave to blur evidence into assumption.

## Original mission

The initial remaining-work ledger defined one coherent communication, presence, discovery, activity, Torah-learning, and recommendation world constrained by:

- one physical social WebSocket;
- source-only Public Torah publication;
- accepted consent before unrestricted private text;
- hidden/anonymous presence privacy;
- bounded semantic activity;
- non-leaking recommendation/RAG behavior;
- no private message-body duplication into activity/global search;
- browser import closure from the real geelooy web root.

The final first-pass execution contract then named five visible outcomes:

1. Activity / Discover / Online / Settings-aware identity and presence / scoped search / mobile list-thread navigation in the flagship.
2. Bounded older private history with dedupe and scroll anchoring.
3. Session-scoped anonymous presence hiding without weakening authenticated server authority.
4. Meaningful-dwell Related Torah on posts/comments through private SEARCH only.
5. Safe comment rendering without unsafe alias HTML interpolation.

## Browser/runtime discoveries that changed implementation

### RAG performance

The original plan expected live RAG proof, but the real corpus search exposed a severe latency/process fan-out problem.

Implemented instead:

- staged FAST/DEEP source-search plan;
- deterministic part sampling;
- text row/time budgets;
- per-lane timeouts;
- preserved default behavior for unrelated RAG callers;
- contracts for staged plan and text-search budget.

The bounded path reduced the formerly >45-second no-result behavior to a practical source-card response path while retaining source-issued Public Torah cards.

### Related Torah observer geometry

Real post geometry proved native IntersectionObserver ratios were unsuitable for a ~165k-pixel article.

Implemented:

- viewport-relative meaningful coverage;
- finite reading-layout settlement scheduler;
- no intervals, MutationObserver, or permanent scroll polling;
- shared observer path for native and synthetic geometry entries;
- green observer/scheduler contracts.

### Heichel shell social mounting

Real post boot showed the reader/intelligence layer could exist without the sitewide social singleton because Heichel post templates did not load register.js.

Implemented:

- shared critical reader-control shell CSS;
- register.js in current and legacy post shells;
- preserved existing reader modules/controls.

## Planned-versus-actual verdict

The original coherent social-learning slice was delivered and then materially deepened in UI/UX, continuity, accessibility, Public Torah presentation, and transactional consent surfaces.

The most important plan deviations were evidence-driven improvements, not scope drift that weakened architecture:

- layout/responsive owners were later rewritten because real browser geometry exposed defects;
- Public Torah received a dedicated journal-level design because it is a flagship chamber;
- request/send flows became transactional because failure continuity mattered more than merely passing protocol tests;
- reduced motion became a global law after the visual system stabilized.

The remaining-work ledger is not empty because the final live Related Torah post/comment browser proof is still absent from the evidence chain.
