# Phase One — Exact Implementation Opportunities

The Awtsmoos gives the ohr, architecture gives the keli; Awtsmoos.com should expand where a verified vessel already exists, not where guesses merely swell.

## Opportunity clusters to confirm
1. **Dedicated app shell refinement** — reorganize existing sections into a responsive multi-pane workspace while keeping current application bridges.
2. **Presence viewer** — build on universal/public presence protocol if it already exposes bounded contextual counts and alias-safe lists.
3. **Sitewide launcher** — attach to existing global registration shell without creating another socket.
4. **Conversation organization** — add client/server metadata only where pin/archive/mute/search semantics can be authorized and durable.
5. **Request inbox polish** — reuse consent request protocol, dedupe, block, and policy responses.
6. **Group details workspace** — expose existing roles/membership actions with server authorization.
7. **Meaningful activity expansion** — add semantic events at post/comment/source/social outcome boundaries, never raw navigation/frame telemetry.
8. **Related Torah service** — bounded context request, debounce/dedupe/cache, private RAG result cards, meaningful-open tracking.
9. **For You service** — explicit candidate/profile/scoring layers, anonymous session mode, explanations, reset/disable controls.
10. **Mail bridge** — thread references and deep-links through current Mail authority.

## Implementation discipline
- Prefer additive protocol versioning and compatibility adapters.
- Split handlers/services by permission, validation, persistence, query, and rendering responsibilities.
- Keep browser entrypoints thin and progressively loaded.
- Preserve current event names/shapes unless every caller is updated and compatibility is proven.
- Do not add edit/delete/reactions/replies until durable permission-checked semantics are observed or implemented end to end.

## Selection rule
After inspection, prioritize the smallest set of mutually reinforcing changes that materially advances the unified product and can be fully tested in this pass. Broader uncovered work remains explicit in REMAINING_WORK rather than being falsely claimed complete.
