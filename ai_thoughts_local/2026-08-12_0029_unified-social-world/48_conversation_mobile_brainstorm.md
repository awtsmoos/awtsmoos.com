# Conversation Mobile Brainstorm

The Awtsmoos is beyond list and room, word and silence, sender and receiver. The next mobile refinement therefore treats private conversation as one spatial journey rather than a desktop inbox squeezed into a narrow vessel.

## Possibilities

1. Let the room header compress after the human begins reading so messages gain vertical space.
2. Keep Back, room identity, and Details permanently reachable even when the header is compact.
3. Use a small tap-to-expand identity row rather than permanently showing secondary subtitle copy on phone.
4. Keep group/member count visible in the compact state as one short chip.
5. Tighten message bubble padding and run spacing on <=430px without reducing text readability.
6. Keep first message in a run visibly authored while continuations drop repeated metadata.
7. Make long timestamps secondary, never dominant.
8. Reduce date-divider ceremony on phone.
9. Preserve provenance/identity; only repeated chrome may compress.
10. Let the composer grow from 44px to a lower phone cap so draft text never consumes half the room.
11. Keep long drafts scrollable inside the composer rather than pushing history away.
12. Give the Send control a clear icon-plus-state treatment on phone without shrinking below 48px.
13. Make `Sending…` visually obvious without replacing the draft or shifting layout.
14. Keep the composer visually anchored above the safe area.
15. Add a subtle top edge/blur so the composer feels attached to the room rather than a separate block.
16. Make the conversation list slightly denser on phone while keeping 56px+ rows.
17. Use stronger unread-title contrast and a quieter timestamp.
18. Keep selected-room state spatially obvious on tablet/desktop but not waste phone width on a desktop accent edge.
19. Improve avatar geometry for narrow lists.
20. Prevent action buttons in list rows from stealing room from title/preview.
21. Keep request/consent actions at 44px+ and never hide them behind collapsible chrome.
22. Animate list→thread and thread→list with transform/opacity only, preserving reduced-motion law.
23. Avoid horizontal swipe navigation unless browser evidence proves it can be done without fighting page back/scroll gestures.
24. Let details drawer enter from the logical side with stable fixed positioning on phone.
25. Use `overscroll-behavior` and scroll-padding so sticky chrome never obscures the newest message.
26. Keep older-history loading anchored to the conversation, not floating in the reading path.
27. Preserve draft continuity when opening/closing details.
28. Keep focus on textarea after recoverable send failure.
29. Do not auto-scroll a human away from older history merely because store refresh arrives.
30. Make all motion finite, purposeful, and fully suppressed under reduced motion.

## Product boundary

No change to:

- private consent authority;
- message transport or persistence;
- group membership rules;
- request semantics;
- read-state authority;
- shared realtime socket;
- Public Torah publication boundary.

## NEXT_ACTION

Turn the strongest possibilities into explicit file ownership: separate mobile header, message rhythm, composer, list density, and spatial transition garments rather than one oversized mobile stylesheet.
