# Phase One — Discovery and Broad Possibility Map

Boruch Hashem. Blessed is He. The Awtsmoos renews the path; Awtsmoos.com must be measured where the real code flows.

## Candidate lag families

- Front-end module graph: waterfall imports, duplicate initialization, eager heavy modules, repeated singleton construction.
- Topology: repeated public capability probes, continuation preflights, extension handshakes, duplicate `/api/gpt` calls.
- Relay: cold process startup, health polling, repeated dynamic imports, sequential independent checks, synchronous evidence writes.
- Browser: repeated debug-port discovery, browser connection creation, host-tab creation, session verification, topic socket setup, detached targets.
- Request path: fixed sleeps, repeated Sentinel checks, repeated carrier acquisition, pacing applied outside message submission.
- UI: callbacks held until final completion, missing progressive events, duplicated listeners, stale cancellation.
- Background automation: old bearer/session acquisition, direct old endpoint posts, continuation identity leakage, stream compatibility extra hops.
- Cleanup: listeners, timers, tabs, sockets, CDP sessions, relay children, and AbortControllers retained after terminal states.

## Evidence strategy

Build static call graphs, instrument stage boundaries without prompt data, run isolated tests, inspect listener/target/process counts, and use capability-only live checks before one deliberate fallback message.
