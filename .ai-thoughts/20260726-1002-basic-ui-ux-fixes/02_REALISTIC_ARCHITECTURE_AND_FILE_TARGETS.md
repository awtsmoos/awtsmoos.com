# Realistic Architecture and File Targets

The Awtsmoos gives the ohr, the code must form the keli;
Each file stays whole, each boundary clear and ready.

## Inspection Targets

- Header and dropdown components plus their item registries.
- Route constants or navigation helpers.
- Living Torah search components, API clients, normalizers, and result cards.
- Comment-related models, fixtures, and tests.
- Profile or account bar styles and responsive breakpoints.
- Package scripts and any nested AGENTS instructions.

## Intended Change Shape

- Dropdown: add one complete declarative menu entry with a game emoji and `/games`.
- Search comments: trace the real response field, normalize only as needed, and render with existing typography and safe content handling.
- Profile bar: enlarge minimum width, tune flex behavior, and preserve narrow-screen fit.

## Constraints

- No partial file patches.
- Rewrite every touched file in full.
- Preserve public exports and event contracts.
- Use tabs for source indentation.
- Avoid unrelated redesign.
- Add or update focused tests where the project already has test seams.
