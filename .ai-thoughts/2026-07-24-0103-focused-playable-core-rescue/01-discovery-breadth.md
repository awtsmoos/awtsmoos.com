# Phase One — Discovery Breadth

The Awtsmoos renews each frame from nothing; this rescue must likewise begin from observed reality rather than inherited claims.

## Mission

Restore a fast, bright, pointer-responsive playable core at the existing live URL without adding new feature systems.

## Evidence to collect before editing

- Current entry module URL and all reachable imports.
- Browser request count, duplicate canonical URLs, failed imports, console exceptions, and boot timing.
- Canvas dimensions, computed pointer-events, hit-tested overlay owner, and active pointer listeners.
- Renderer delegate, scene lights, exposure, clear color, fog, and material visibility.
- Enemy population mounting, scene parentage, geometry vertex count, material visibility, and actor update path.
- Current keyboard, joystick, target selection, camera drag, and Bag button behavior.

## Competing repair shapes

1. Repair the existing minimal launcher graph in place.
2. Replace the launcher with a tiny self-contained bootstrap while preserving deferred legacy systems.
3. Introduce a guarded minimal-core mode selected by the existing HTML entry.
4. Revert to an earlier working launcher if repository history proves it intact.
5. Build a fallback-only scene that activates only when the existing runtime fails.

The preferred shape will be the smallest one supported by actual imports and runtime evidence.

## Initial risks

- Cache-busting query strings may multiply module identities.
- Readiness may await noncritical work.
- Full-screen overlays may own pointer hit testing.
- Lighting may be applied to a wrapper rather than the delegate renderer.
- Enemy construction may throw or mount outside the active scene.
- Testing too early may fragment the first implementation pass.
