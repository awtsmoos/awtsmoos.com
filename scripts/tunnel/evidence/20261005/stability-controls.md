# Awtsmoos bounded stability controls

The live baseline tests real localhost Mac actions and the authenticated device instruction bridge. It does not invoke ChatGPT user OAuth MCP tools. Health liveness alone is not command execution proof.

GET /healthz remains lightweight process liveness. GET /readyz reports HTTP 200 only when the connection receipt is registered, parent and child PIDs are alive, and server testimony is no older than 90 seconds. Otherwise it reports 503 with a specific reason. Its commandExecution field remains not_probed; run an owned harmless command for execution proof.

The awtsmoos_action_schema MCP tool accepts targetAction or targetActions (1–16 exact names). Generic tunnel action actionSchemaTrace accepts the same bounded array. Duplicate names are removed. These schemas preserve existing generic fallback behavior: obtaining a schema is not proof that an action is registered. Consult the catalog for registered names. Batching performs discovery only and reduces serial round trips.

MCP route failures identify requested action, actual API error, and HTTP status instead of a generic server error. Authentication and scope checks remain in the existing routes.

instructionResolve retries one lost response only while the same websocket remains open. It does not retry mutations, retry indefinitely, or claim remote instructions exist while offline. A server restart can still produce an explicit local-only result during reconnect.

A write can opt into performanceDiagnostics:true. timingMs separates preparation, execution, and durable provenance. Default response identity remains unchanged. Durability, integrity verification, operation transitions, and outbox delivery remain enabled.

The stress harness uses owned fixtures, independent completion-driven loops, bounded request deadlines, exact stdout and file hashes, out-of-order and duplicate chunks, commit replay, and cancellation of only its own jobs. It removes only its owned fixture directory.
