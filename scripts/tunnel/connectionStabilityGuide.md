# Awtsmoos connection stability and shared plugin instructions
The connection parent records bounded transitions in durable connection-flight.json. tunnelConnectionDiagnostics reports retained transitions, registration duration, reconnect pressure and recorded outages. Logs omit request bodies and credentials. Wake/scheduler gaps are observations, not automatic restart orders.
Bootstrap has a 45-second default deadline. Once an open transport is observed, registration receives a separate 30-second bound, within a finite startup window. A delayed parent scheduler receives only one five-second grace. Exact child and timer generations fence old callbacks.
Brief registration does not reset reconnect pressure. One minute of sustained registration resets it. Child restart delay is jittered and capped; the existing one-timer WebSocket reconnect policy remains authoritative.
Shared recovery lease actors defer to a verified living installer owner using root, PID and process-start signature. Service repair is bounded to 15 seconds and 128 KiB output; existing OS supervisor ownership and emergency fallback are preserved.
Candidate install readiness defaults to eight samples and at least 15 seconds, retaining local action, registration, identity and version checks. Overrides exist for controlled test fixtures. This is not an overnight endurance proof.
All four plugin skills are exact instruction bodies under shliach.skill.instructions, shliach.skill.tunnel-workflow, shliach.skill.novel-voice and shliach.skill.poetic-code. instructionCatalog names resource discovery. instructionResourceCatalog paginates all skill resources; instructionResourceGet requires an exact cataloged path and supports expectedHash, offset and maxChars. Continue until nextOffset is null. Offsets are UTF-16 code units, not bytes. Legacy originals remain archival and never override modern transport contracts.
Plugin source is preserved under plugins/awtsmoos-shliach. Released native skill mirrors live under agent/lib/instructions/pluginSkills. Their index contains SHA256 for every resource; tests compare exact skill bodies and reconstruct paginated originals. Update both sources together and regenerate the resource index.
tunnelWorkFailure records an explicit failed attempt under optimistic revision. Default retry budget is three; exhaustion blocks the work record and names inspection as the next action. It never retries a command automatically. Preserve job/receipt IDs and observe uncertain mutation outcomes before any resend.
Existing reserved scheduler lanes, bounded worker/browser queues, durable command/transfer identities, stale-child fences and frontend release evidence are retained. Local, server, authenticated-client and rendered-frontend checks are separate evidence boundaries.

Before releasing changed plugin skills, run node scripts/tunnel/syncPluginInstructionMirror.cjs --write, review the generated source, and build a new native release. This regenerates discovery for every skill, including newly added ones. Production activation checks mirror consistency and refuses divergence.
