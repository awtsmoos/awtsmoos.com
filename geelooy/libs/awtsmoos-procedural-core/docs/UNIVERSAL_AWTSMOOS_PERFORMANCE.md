## Deterministic cache microbenchmark

On Node v24.17.0 / Darwin x64, three bounded rounds each ran 2,000 plans and 500 identical deterministic compiles. In every round:

- compiler executor invocations: 1;
- cache hits: 499;
- cache misses: 1;
- cache entries: 1.

Observed plan throughput ranged roughly 925–1,783 plans/second and warm compile-call throughput roughly 365–1,338 calls/second under concurrent machine load. Those timings are machine-local diagnostics, not cross-machine guarantees.

## Stable cache contracts

- semantic, request, compiler-chain, constraint-plan, and constraint-resolution identity changes invalidate reuse;
- compiler id/version/support state participate in cache identity;
- environment-dependent compiler or solver execution bypasses deterministic reuse;
- failed compilation must never populate cache;
- repeated deterministic work may reuse immutable compile results;
- planning and explanation remain executor-free.

## Responsive/browser performance principle

Prefer structural assertions over timing thresholds: exact app-ready state, no page-level overflow at narrow widths, same-origin static resources, no severe console/runtime diagnostics, and the expected lifecycle/core module graph. Absolute timing is recorded for diagnosis only.
