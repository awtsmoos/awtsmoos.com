# Portal Universal Data — Describe Anything Without Teaching Portal Every Noun

Boruch Hashem. Blessed is He.

The Awtsmoos renews tree, river, building, creature, garment, machine, weather, and
future unnamed form before a schema may call them different. Awtsmoos.com lets their
finite differences live in semantic data and specialist compilers while the common
language remains stable enough for worlds not imagined when the kernel was written.

## Root principle

Geometry is an artifact, not the root ontology.

A Portal definition describes **intent**. Registered compilers decide how requested
intent becomes visual geometry, collision, navigation, rigs, physics, audio, metadata,
or other supported artifacts.

## Canonical definition shape

```js
const definition = {
	id: 'market-arch-613',
	kind: 'architecture.arch',
	traits: {
		structural: {values: {loadBearing: true}},
		walkable: {values: {top: true}}
	},
	relationships: [{
		type: 'spans',
		from: 'market-arch-613',
		to: ['pier-a', 'pier-b']
	}],
	constraints: [{type: 'clearance', value: {amount: 2.4, unit: 'm'}}],
	compile: {
		required: ['visual', 'collision'],
		optional: ['navigation'],
		quality: 'gameplay'
	}
};
```

The canonical Procedural Definition can also carry behaviors, quantities/units,
semantic references, resources, ordered actions, provenance, extensions, revision,
and deterministic seed data.

## Why traits instead of one giant class tree?

One thing may simultaneously be `living`, `container`, `walkable`, `weatherable`,
`riggable`, or `structural`. Traits compose without forcing every future noun into a
single inheritance hierarchy foreseen by today's code.

Implementation classes remain valuable for registries, compilers, planners,
validators, adapters, and runtime services. Authored reality stays data-composed.

## Relationships make the world a graph

Relationships use generic `from` / `to` endpoints and can express meanings such as:

- `inside` / `contains`
- `attachedTo`
- `supportedBy`
- `spans`
- `growsFrom`
- `follows`
- `carvedInto`
- `surrounds`
- `drainsInto`
- `connectedBy`

The kernel need not hardcode every relationship meaning. Domain validators and
compilers may register deeper semantics above the generic portable descriptor.

## Constraints preserve truth across implementations

Constraints currently remain portable JSON-safe definition data. Domain authorities
may interpret meanings such as clearance, slope, containment, support,
no-intersection, silhouette, biological proportion, spatial budget, or other laws.

A compiler may satisfy a constraint natively, delegate it, defer it, or report that
its capability cannot fulfill it. It must not silently claim success.

## Artifact requests

The same definition can produce different requested manifestations:

- editor preview: `visual + metadata`
- gameplay: `visual + collision + navigation + interaction`
- animation: `visual + rig + animation`
- simulation: `geometry + physics + metadata`
- export: `visual + material + export`

The semantic definition remains stable while compile policy changes.

## Provenance

Portal planning exposes a stable `definitionHash`. Compilation carries the canonical
artifact request into every specialist. Compile outputs, explanations, and Universal
World resources preserve both values so future editors can answer:

- Which exact authored definition produced this?
- What artifact channels were requested?
- Which dependencies existed?
- Was fallback used?
- Which result type appeared?

## The honest meaning of “generate anything”

The **grammar** is open to any noun without kernel changes. The **runtime ability** to
produce a high-quality artifact depends on registered compiler capability.

Adding `architecture.cathedral`, `biology.beetle`, or `future.quantum-garden` should
require a domain compiler/plugin, not a new Portal verb or a new root data format.
