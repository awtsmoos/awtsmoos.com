# Awtsmoos Procedural Language — Public Creation Portal

The Awtsmoos renews definition, world, compiler, artifact, and future kind before a finite API can name the way;
Awtsmoos.com exposes one stable package doorway so new domains may deepen the language without forcing callers through private source paths every day.

## Supported import

```js
import {
	createAwtsmoosCreationPortal
} from "@awtsmoos/procedural-core/procedural-language";
```

This is the supported public subpath for the modern semantic procedural language.

It is additive. Historical package entry points such as `procedural-object`, `universal-api`, `reality`, and the package root remain unchanged.

## Simple surface

The Creation Portal intentionally exposes six verbs:

- `define(input)` — normalize Definition-compatible semantic data.
- `generate(kind, options)` — invoke registered data-driven authoring generators.
- `request(input)` — normalize renderer-neutral artifact requirements.
- `plan(definition, request)` — explain compiler-chain coverage without executing compilers.
- `compile(definition, request, options)` — produce requested artifacts through the private compiler graph and cache.
- `inspect()` — return JSON-safe schemas, channels, capabilities, and registry evidence.

The Portal is frozen. Its advanced authority remains private behind the facade.

## Anything/everything principle

The public API does not need one method for every noun in creation.

A future semantic definition may use a kind such as:

```js
const definition = portal.define({
	kind: "future.anything",
	properties: {
		purpose: "domain-defined"
	}
});
```

Domain plugins and compiler capabilities determine whether requested artifact channels can be planned and compiled. New nouns therefore expand registries and data contracts rather than expanding the top-level API indefinitely.

## Advanced public symbols

The same subpath also exposes:

- `AwtsmoosCreationPortal` and `createAwtsmoosCreationPortal`;
- `AwtsmoosProcedural` and `createAwtsmoosProcedural`;
- `UniversalSemanticKernel` and `createUniversalSemanticKernel`;
- procedural Definition helpers and patch transactions;
- artifact requests and artifact-channel discovery;
- capability and schema discovery;
- versioned language contract constants.

Use the simple Creation Portal by default. Reach for the advanced facade or isolated kernel only when authoring tools, compiler plugins, or diagnostics genuinely need deeper ownership.

## Stability law

Keep renderer objects, executable compiler functions, and domain implementation details behind the package boundary. Public values should remain serializable or intentionally class/factory entry points. Add new semantic power through definitions, traits, relationships, constraints, generators, compiler registrations, and artifact channels before inventing another public verb.
