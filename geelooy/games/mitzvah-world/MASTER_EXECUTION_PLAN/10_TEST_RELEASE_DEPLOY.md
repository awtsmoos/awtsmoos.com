# 10 — Test Gates, Release, Reconciliation, Deployment

## Authored-source gate
- [ ] every touched source starts with required B"H header in language-appropriate comment form;
- [ ] every touched authored JS file is strictly under 120 lines;
- [ ] tabs, extensive JSDoc, readable formatting; no minification/compressed statements;
- [ ] `node --check`/parser checks on touched JS/MJS;
- [ ] `git diff --check`;
- [ ] generated compact bundles are regenerated by official tooling, never hand-edited.

## Core correctness tests
- [ ] deterministic same-seed tests;
- [ ] no NaN/Infinity, valid bounds/indices/topology;
- [ ] fuzz random valid/invalid configs;
- [ ] huge-count clamps prevent runaway recursion/allocations;
- [ ] renderer-neutral imports in Node/Worker/no-DOM contexts;
- [ ] save/load and schema migration invariants;
- [ ] exact-once transaction tests;
- [ ] asset/material fallback tests;
- [ ] weather/tree/world capability manifests remain truthful.

## Runtime world tests
- [ ] every official card routes to its exact manifest;
- [ ] cold/warm/offline first control;
- [ ] actual player movement proof;
- [ ] zero uncaught runtime errors during boot and first minute;
- [ ] save/reload preserves meaningful state exactly once;
- [ ] missing optional assets/services degrade without boot failure;
- [ ] world switch cleanup and repeated re-entry;
- [ ] mobile/background/resume/context-loss recovery.
## Visual/performance test matrix
- [ ] Blank Meadow baseline;
- [ ] Living Village inspectability;
- [ ] Great Valley streaming;
- [ ] deep forest/foliage overdraw;
- [ ] city/crowd benchmark once city exists;
- [ ] clear enormous vista;

Record: boot timings, first-control, frame-time percentiles, RAM, GPU resources, draw calls, loaded bytes, Worker count, runtime errors, save/reload result.

## Git reconciliation
1. [ ] Fetch origin and inspect canonical status/HEAD/origin/log/reflog/worktrees/stashes.
2. [ ] Re-run lane tests on current lane commit.
3. [ ] Stage only owned files and create evidence-based commit(s).
4. [ ] Reconcile latest origin/main and canonical concurrent work without destructive reset/clean/stash.
5. [ ] Resolve conflicts by understanding both implementations; never silently drop concurrent work.
6. [ ] Run impacted + broad regressions after reconciliation.
7. [ ] Bring final work into canonical `/Users/awtsmoos/work/awtsmoos.com` `main`.
8. [ ] Push and verify `git rev-parse HEAD == git rev-parse origin/main`.

## Deployment
- [ ] immutable assets first, mutable catalogs last;
- [ ] build provenance records exact Git commit, catalog/schema versions;
- [ ] deploy canary before broad release where infrastructure supports it;
- [ ] run synthetic production boot/play after deploy;
- [ ] verify representative production URLs/hashes/CORS/MIME/cache;
- [ ] watch error/latency/resource dashboards;
- [ ] rollback automatically/manually if release gates regress.

Never report `LIVE` until public runtime/URLs have been independently checked after deployment.
