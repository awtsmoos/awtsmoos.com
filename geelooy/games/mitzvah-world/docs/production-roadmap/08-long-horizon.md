# Long-Horizon Platform and Content Evolution

## Data-driven world growth

- Separate engine code from declarative quests, dialogue, region configuration, NPC schedules, biome definitions, material intent, and landmarks.
- Validate every referenced quest target, NPC, landmark, region, asset, localization key, and world-event identity at build time.
- Detect dead content, orphaned assets, missing aliases, circular dependencies, and disconnected map topology.

## Developer tooling

- One command for focused MitzvahWorld validation.
- One command for asset dry-run/import.
- One command for transactional asset publication and verification.
- One command for official build plus production tests.
- One command for browser/mobile smoke acceptance where automation permits.
- Emit machine-readable receipts for every substantial operation.

## Documentation

- Maintain art direction, world bible, naming conventions, event schemas, Procedural Core APIs, asset ingestion/publication, rollback, save migrations, performance tiers, mobile input, deployment, and Tunnel recovery docs.
- Keep operational documents free of secrets.

## Catalog growth

- Add compact bootstrap indexes, browser-side semantic index caching, generation-based invalidation, compressed delivery, and eventually paging/indexed search when the asset universe becomes large.
- Keep aliases backward compatible across old cached clients.

## Content operations

- Build repeatable pipelines for new quests, regions, NPCs, models, sounds, materials, localization, and seasonal/world events without engine surgery.
- Measure player behavior and failures before adding complexity merely because it is possible.
- Preserve the core identity: one connected living world where Torah, mitzvos, kindness, learning, construction, nature, and civilization visibly affect one another.
