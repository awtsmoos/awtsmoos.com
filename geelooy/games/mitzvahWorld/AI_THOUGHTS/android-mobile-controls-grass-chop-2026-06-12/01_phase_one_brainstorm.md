# Phase One Brainstorm — Android Mobile Controls / Grass / Choppy Approach

User moved us to Android tunnel: `awt-u0_a300-26940`, root `/storage/emulated/0/Documents/git/awtsmoos.com`.

Observed from screenshots:
- Mobile HUD: joystick bottom-left, action bar centered bottom, jump/action arrow bottom-right. Action bar and controls overlap hard on portrait Android.
- Joystick direction is inverted: player moves opposite of joystick face.
- Health changes prove fox/animal attacks happen, but approaching player is very choppy.
- Grass is still too flat / cheap; user wants custom grass material generated by shader one time and better.

Possible causes:
1. Mobile joystick DOM positions are hard-coded bottom/left/right with no responsive safe-area logic.
2. Mobile input vector may map joystick up to wrong FORWARD/BACKWARD flag, especially after W/S reversal or existing mobile coordinate system. Need inspect mobile input files.
3. Choppy approach likely from animal AI using navigator + worldOctree raycast every frame, collision grounding every frame, or heavy raycast/geometry checks near player.
4. Choppy approach might be from attack VFX setTimeout/emissive traversal or repeated `navigator.move` ground sampling via octree.
5. Custom grass likely comes from `VillageGrassField`, `fieldRecipes`, `FoliageAtlas`, `ProceduralTerrain` texture. Need inspect active grass code.
6. Shader one time means create one shared shader/canvas/DataTexture material and reuse, not per-blade DOM texture loads.

Big improvement ideas:
- Use CSS `env(safe-area-inset-*)`, clamp portrait action bar width, move action bar above bottom nav, shrink mobile buttons, reserve left/right touch zones.
- Add `body.mobile-game` or broad media queries max-width 800 and pointer coarse.
- Joystick: invert y axis or swap FORWARD/BACKWARD for mobile only, independent of desktop key reversal.
- Add diagnostic event for joystick vector mapping.
- Animal AI: use squared distances, reuse vectors, avoid navigator orbit/chase raycast every frame; throttle terrain grounding to 10 Hz; precompute player position; smooth velocity with acceleration.
- Animal approach: use simple steering to target standoff, not expensive pathfinding; no octree while in close chase unless obstruction detected.
- Attack: debounce VFX and material traversal, use pooled meshes, no setTimeout storm.
- Grass shader: add shared `VillageGrassShader.js` material using vertex displacement in onBeforeCompile or ShaderMaterial, DataTexture color ramp once.
- Grass fields: replace geometry cards with instanced blades using shared material; update time uniform once per frame per material.
- Ensure grass is `skipRaycast`, `skipOctree`, no collision.

Files to inspect:
- mobile controls / joystick CSS and JS: search `joystick`, `setInput`, `FORWARD`, `mobile`.
- `main.css`, `mainThread/ui`.
- `VillageAnimalMob`, `VillageGroundNavigator`.
- `VillageGrassField`, `fieldRecipes`, `FoliageAtlas`, `ProceduralTerrain`.
