# bh54 Moving Push Block Hardness

## What is wrong
The moving push block is visual + custom shove only. It is not in the worldOctree, and a moving mesh in the static octree would be stale anyway. Player ground detection only raycasts the static worldOctree, so the moving block cannot be treated as floor by the normal physics stack. When the player lands on it, gravity continues and the player falls through.

## Correct fix
Keep the moving block out of the octree for performance, but make it a tiny dynamic platform solver:
- one pathBox broadphase around the whole moving route,
- one live AABB check for the current block,
- if player feet are above/near top and within XZ, snap player collider to top,
- zero downward velocity,
- carry player by block delta,
- update mesh, modelMesh, emptyCopy, nonRotatingEmptyForMovement, collider start/end.

## Also
Make the moving block visually thicker/harder.
Bump cache for MovingPushBlock through DvarimExports and loader chain.

## Verification
- node --check MovingPushBlock and export/cache files.
- Static checks for: supportPlayerOnTop, collider.start/end update, zeroing velocity.y, pathBox broadphase, bh54 exports.
