# bh52 What Was Wrong And The Actual Fix

## Bugs from screenshots
1. Mezuzah was on the outside face of the right post:
   - right post sits at z = +1.65
   - outside face is around z = +2.01
   - inside doorway face is around z = +1.24
   - current mezuzah z=2.18 is outside.
2. Doorway still had a brown closed door slab.
   - user wants open doorway; finish is touching mezuzah.
3. Moving push block visually moved, but did not push reliably.
   - it moved mesh only and nudged one player vector;
   - physics/collider could overwrite it next frame.
4. Console spam: `approach npc msg` not found.
   - `dialogues.js` defines it, but `gameUI/index.js` does not import/include dialogues.
5. SPIKE_RESET_TRACE logging is hot and noisy.
   - remove production spam / gate it.

## Fixes
- Remove visible door slab from level geometry.
- Move mezuzah to inside right post: z about +1.24.
- Move InteractiveDoor trigger to the mezuzah itself and auto-navigate on touch.
- Make MovingPushBlock use swept AABB and move mesh, modelMesh, collider start/end.
- Give MovingPushBlock a safe generated RGBA texture.
- Include dialogues in gameUI index and bump UI cache.
- Gate spike reset logs behind debug flag.
