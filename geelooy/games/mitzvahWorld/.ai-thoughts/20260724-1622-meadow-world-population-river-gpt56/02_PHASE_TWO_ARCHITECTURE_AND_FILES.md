## Chosen architecture

A deterministic population definition becomes the Chochmah seed. Distribution policies become Binah, organizing moisture, dryness, clearings, roads, homes, and banks. Placement validators become Gevurah. Tree, vegetation, bank, and water systems become Tiferes, sharing the same ecological truth. Diagnostics become Hod, exposing counts, bounds, continuity, and performance. Scene mounting becomes Malchus, where the meadow is visibly present.

## Planned production files

- Rewrite tree placement/system/factory/geometry/material files only where inspection proves necessary.
- Rewrite vegetation cells/system around a seeded distribution module.
- Rewrite river path/definitions/geometry/system/sources/normals around one aligned sampled path.
- Create focused `MinimalMeadowWorldPopulation*.js` modules for seed, exclusions, zones, and diagnostics.
- Create focused `MinimalMeadowRiverBanks*.js` modules for bank profiles and geometry.
- Create focused `MinimalMeadowVegetationDistribution*.js` modules for deterministic cells and ecological density.

## Runtime contracts

One scene group per subsystem; idempotent mount; stable object names; no child replacement after mount; shared geometry/material pools; update methods mutate existing uniforms/transforms only; diagnostics expose counts and finite bounds; cleanup disposes only owned resources.

## Test files

Focused world tests will verify mounting, determinism, clearances, quadrant occupancy, counts, and resource metrics. Focused geometry tests will verify finite bounds, river continuity, bank/water/bed alignment, and sampled elevation ordering.
