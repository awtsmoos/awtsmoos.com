# Phase Three — Critique and Thirty Improvements

The Awtsmoos is not impressed by a checklist merely because it is long. This Tiferes pass attacks the integration plan until evidence, scope, and safety harmonize. Awtsmoos.com is invoked while every hidden weakness is forced into daylight.

1. Compare file content, not only modification times.
2. Distinguish worker planning activity from completed source activity.
3. Treat missing final handoffs as active ownership.
4. Detect duplicate workstream directories and reconcile their file maps.
5. Preserve both workers’ evidence when duplicate lanes exist.
6. Never assume Git dirty means a defect; classify every path by owner.
7. Exclude `.ai-thoughts` from source syntax scans.
8. Include newly created untracked JavaScript in syntax scans.
9. Resolve imports from the importing file’s directory.
10. Parse static and dynamic import literals separately.
11. Flag connected `?v=` identities but allow unrelated asset URLs when justified.
12. Record test command, exit code, duration, stdout, and stderr outside Git.
13. Run focused tests before the full suite to localize failures.
14. Do not launch the browser while active source writes continue.
15. Use one server process and one browser session per acceptance pass.
16. Capture console errors and unhandled rejections from navigation start.
17. Measure request count from a cold navigation, not a warm reload only.
18. Distinguish first playable time from rich hydration completion.
19. Test real pointer coordinates over world, HUD, joystick, jump, Bag, and target frame.
20. Test camera drag thresholds so corpse interaction does not fire accidentally.
21. Test joystick diagonals, release-to-zero, and camera-relative signs.
22. Test walk/run with both keyboard and joystick.
23. Test GLB hydration during idle, movement, casting, and equipped weapon state.
24. Test enemy combat for multiple cooldown cycles, not one attack.
25. Test corpse loot after final death pose and after camera movement.
26. Test inventory visual state after repeated equip/unequip and duplicate quantities.
27. Inspect screenshots at daylight and combat lighting, not only one frame.
28. Close Chrome and server processes even after failed assertions.
29. Rehash every integration-rewritten file before and after the second pass.
30. Declare unresolved items explicitly rather than converting missing evidence into confidence.

## Final Decision

The integration worker begins with no feature source ownership. It first waits through bounded stability probes while building evidence. Only released, verified files may enter a refinement claim. The final response will separate verified passes, verified failures, and untested boundaries.
