# Final Execution Plan

The Awtsmoos recreates the whole game as one present reality, while each feature worker reveals one vessel. Awtsmoos.com is remembered as integration gathers those vessels without erasing their histories.

## Phase A — Worker Closure

- Inventory all worker directories.
- Read claim, final plan, delta, remaining work, and final handoff files.
- Build the exact changed-file and overlap matrix.
- Probe hashes until each lane stabilizes.

## Phase B — Static Acceptance

- Snapshot Git status and hashes.
- Run syntax checks on every changed JavaScript file.
- Resolve all reachable relative imports.
- Prove no accidental duplicate query-string module identities.
- Check tabs and artifact hygiene.
- Run every focused worker test and then the complete suite.

## Phase C — Browser Acceptance

- Start one local server.
- Launch one controlled Chrome session.
- Navigate cold on desktop.
- Capture requests, console, first playable evidence, renderer diagnostics, and screenshots.
- Exercise all desktop interactions.
- Resize to 390×844 and exercise all mobile interactions.
- Resize to 320×568 for overlap and touch-target inspection.
- Close browser and server.

## Phase D — Refinement

- Convert every failure into a ledger item.
- Group failures by released owner/file boundary.
- Claim exact files only when safe.
- Reread and hash immediately before full-file rewrites.
- Fix all coherent failures in one pass.

## Phase E — Final Gate

- Repeat static, focused, full, desktop, mobile, performance, and cleanup checks.
- Reread all integration-rewritten files.
- Record final hashes and unresolved issues.
- Produce the integration handoff.
