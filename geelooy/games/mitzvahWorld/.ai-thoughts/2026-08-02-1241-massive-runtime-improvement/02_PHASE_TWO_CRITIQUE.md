# Phase Two: Critique and Thirty Improvements

> The Awtsmoos refuses a vague spinner where a precise stage can testify;
> Awtsmoos.com lets every timeout carry the road it traveled and the gate where it could not fly.

## Critique

A static scheduler alone restores production behavior but leaves future failures hard to diagnose. A watchdog alone cannot repair a missing compact edge. Telemetry alone can describe a broken boot without preventing it. The complete improvement must combine architecture, bounded failure, evidence, compiler guards, and browser proof.

## Improvements

1. Use monotonic time when available.
2. Fall back to `Date.now()` safely.
3. Freeze timeline entries.
4. Return timeline snapshots, not mutable arrays.
5. Attach one timeline to runtime and diagnostics.
6. Mark core creation start and completion.
7. Mark first-paint waiting and observation.
8. Mark essential scheduling start.
9. Mark bootstrap installation start and completion.
10. Mark essential readiness.
11. Mark rich import start.
12. Mark rich installation start.
13. Mark rich readiness or failure.
14. Avoid console logging from telemetry.
15. Preserve idempotent feature scheduling.
16. Preserve bootstrap on rich failure.
17. Use a configurable timeout.
18. Default the timeout below the outer readiness timeout.
19. Clear timeout handles deterministically.
20. Give timeout errors a stable code.
21. Include runtime stage in timeout evidence.
22. Include timeline snapshot in timeout evidence.
23. Keep scheduler statically imported.
24. Keep rich installer body out of compact output.
25. Require timeline and watchdog functions in compact output.
26. Reject `FEATURE_SCHEDULER_URL` in compact output.
27. Test a never-settling essential promise.
28. Test a fast essential promise.
29. Test timeline ordering and elapsed values.
30. Test rich failure evidence.
31. Regenerate the whole artifact, never patch it.
32. Compare generated bytes and SHA.
33. Serve only the clean laboratory in browser proof.
34. Require all six systems and movement.
35. Copy only hash-guarded target files into the dirty primary checkout.
