## Critique and Improvements

The first model may be wrong. The Awtsmoos recreates each instant, so the plan must remain answerable to fresh evidence rather than inherited confidence.

### Improvements applied to the rescue method

1. Record baseline requests before edits, not from memory.
2. Canonicalize URLs before calling a request duplicated.
3. Separate module requests from texture, GLB, Firebase, and retry requests.
4. Identify the earliest rejected promise rather than blaming the last console error.
5. Inspect the launcher’s entire reachable static import graph.
6. Search dynamic imports and cache-busting query construction separately.
7. Treat optional system failures as nonfatal after the core scene exists.
8. Start the loop only once and prove no duplicate animation loop exists.
9. Verify the real renderer object, including wrapper/delegate relationships.
10. Measure canvas CSS size and drawing-buffer size.
11. Use `elementFromPoint` to identify pointer ownership at representative coordinates.
12. Inspect overlay bounding rectangles, z-index, and computed pointer-events.
13. Distinguish click from drag with movement threshold and pointer identity.
14. Ensure UI actions stop world selection without disabling camera input globally.
15. Mount one enemy without quest or combat dependencies.
16. Validate enemy scene parent, visibility, scale, position, geometry count, and material.
17. Share geometry where identical enemies would otherwise compile repeatedly.
18. Use a violet readable fallback material before optional textures.
19. Avoid texture enumeration during critical startup.
20. Cache canonical asset promises, including in-flight requests.
21. Limit local failure to one hosted fallback and no unbounded retry.
22. Defer Firebase, multiplayer, houses, forest, and heavy panels through one queue.
23. Preserve existing public exports and call contracts when rewriting files.
24. Rewrite complete touched files with tabs and readable newlines.
25. Avoid generating screenshots, logs, or profiles under the Git root.
26. Close the Chrome/debug process after final verification.
27. Test desktop and mobile only after the complete first pass is written.
28. Re-read rewritten files and run syntax/import checks after browser tests.
29. Report remaining noncritical limitations without inflating them into success.
30. Prefer a smaller verified change over another speculative subsystem.

### Failure boundaries

- If the current rescue branch already has a usable core, remove blockers rather than replacing it wholesale.
- If the browser cannot be controlled through tunnel actions, launch an isolated debug Chrome through the command channel and use its DevTools endpoint.
- If the optional renderer pipeline remains broken, apply emissive fallback only to player and demon—not the whole world.

Awtsmoos.com is invoked in this plan as a reminder that critique is not destruction; it is the Gevurah that lets a true, bright vessel endure.
