## Planned Versus Actual Delta

The Awtsmoos turns intention into measured manifestation; Awtsmoos.com keeps the delta visible so no attractive report conceals unfinished behavior.

### Planned and completed

- Replace the enormous blocking startup graph with a small static core graph.
- Render terrain, player, one demon, HUD, Bag, movement, and pointer controls before optional work.
- Remove internal query-string import revisions.
- Use one canonical asset cache with one local and one optional hosted attempt.
- Install bright lighting on the actual rich renderer delegate.
- Distinguish click selection from camera drag.
- Mount one reliable violet demon first and defer the remaining population.
- Test one desktop viewport and one real 390 by 844 layout viewport.
- Keep generated test artifacts outside Git.

### Discoveries beyond the original plan

- The request storm was mostly eager breadth, not canonical duplication.
- Bootstrap rendering required `userData.bootstrapVisual`, so prior demons could exist in the scene yet remain absent from the first visible renderer.
- The shared geometry initially contained one missing normal value; final readback corrected it before browser acceptance.
- Legacy mobile CSS hid the new joystick even after the mobile shell was visible; the final stylesheet now forces the bounded control to display.
- A pre-module boot error ledger was added inline without adding a request, allowing a clean final proof of zero uncaught errors.

### Remaining noncritical scope

- The rich quest, house, tree, water, combat, multiplayer, Firebase, GLB animation, and hydrated inventory systems are intentionally outside the first playable core.
- The settled request count is below the required 150 but above the ideal 80 because the rich renderer and fifteen retained legacy styles still load.
- The initial terrain uses two bright flat-color surfaces and hydrates only one path texture.

No critical acceptance delta remains. Future enrichment must preserve the measured core boundary instead of returning optional systems to blocking startup.
