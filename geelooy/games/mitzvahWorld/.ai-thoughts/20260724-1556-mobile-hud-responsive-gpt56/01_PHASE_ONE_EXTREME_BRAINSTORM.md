## Phase one — unconstrained responsive possibilities

The Awtsmoos contains joystick, Bag, target, action bar, rail, safe area, and world without overlap; Awtsmoos.com asks the finite stylesheet to reveal that unity through measured exclusions.

1. Import one dedicated mobile stylesheet after the pointer corrections.
2. Keep desktop styling unchanged outside mobile media queries.
3. Collapse the game rail into a bottom-safe compact strip rather than a centered glass wall.
4. Give the rail a bounded height and horizontal overflow instead of wrapping into multiple rows.
5. Keep the Walk/Run mode control visible and separate from secondary actions.
6. Hide labels on narrow phones while preserving accessible button names.
7. Keep controls at least 44×44.
8. Reserve the lower-left quadrant for joystick travel.
9. Reserve the lower-right quadrant for jump.
10. Place the combat hotbar above the browser-safe bottom and above touch controls.
11. Keep target frame below browser chrome and above the rail.
12. Make the Bag a bounded modal sheet with explicit header, close button, scroll body, and sticky details.
13. Use `100dvh` and safe-area variables rather than raw `100vh` for mobile panels.
14. Prevent Bag height from extending behind browser chrome.
15. Reduce empty Bag slots on mobile without changing inventory data.
16. Keep equipped slots visible in a compact horizontal row.
17. Make the item detail panel remain visible through sticky placement.
18. Ensure no transparent full-screen child intercepts canvas pointers.
19. Preserve keyboard focus rings.
20. Support 320×568, 390×844, and larger phones.
21. Use landscape-specific reductions.
22. Avoid changing runtime state or inventing display-only equipment.
23. Verify computed rectangles and `elementFromPoint` after the complete pass.
24. Verify real Walk/Run state through the existing movement worker’s diagnostics.
25. Verify coat, staff, sword, demons, terrain, houses, river, roads, and trees only as read-only integration observations.
