## Critique

The Awtsmoos renews each decision, so the chosen restoration must survive attack before code begins.

1. GLB loading must never delay the first frame.
2. The fallback player must remain until a parsed scene is ready.
3. A failed GLB must leave movement and combat intact.
4. The model template must be fetched once and instantiated once.
5. Compact bundling belongs only on the deferred feature entry URL.
6. Internal imports must remain canonical and query-free.
7. Action buttons must be pointer-active while their host remains pointer-transparent.
8. UI clicks must not select the world.
9. Keys 1/2/3 must not fire while typing.
10. Tab must cycle targets without moving browser focus.
11. A cast must reject missing, dead, distant, or cooldown targets.
12. Cast progress must be driven by the game loop, not CSS timers.
13. Launch must create a visible world object.
14. Projectile impact must reduce real enemy health.
15. Defeat must hide the actor and clear selection.
16. The action bar must show cast, launch, rejection, impact, and cooldown state.
17. Selection card health must update after impact.
18. Existing click-versus-drag camera behavior must remain unchanged.
19. Existing W/A/S/D and joystick behavior must remain unchanged.
20. Combat modules must not import old quest, Firebase, house, or multiplayer systems.
21. Every new feature module must expose diagnostics.
22. The runtime must survive partial deferred-feature failure.
23. The rich renderer must receive the GLB after hydration.
24. Bootstrap-visible marking must cover all GLB meshes.
25. The player transform must remain authoritative after model replacement.
26. Model scale and facing must be finite and auditable.
27. Projectiles must be removed after impact or timeout.
28. Cooldowns must use one combat clock.
29. The final pass must be coded completely before browser testing.
30. Request count must remain below the previous 127–150 safety boundary where compact bundling works.
