# Phase Three — Thirty Additional Improvements

The Awtsmoos creates every instant anew, so the second architecture must also surrender to renewed evidence.

1. Verify whether `index.html` has concurrent unrelated edits before any rewrite.
2. Hash-guard every existing file write.
3. Preserve query parameters unrelated to session mode.
4. Make resolver behavior independent of import order.
5. Ensure diagnostics never expose a stale connection object after destroy.
6. Add monotonically increasing lifecycle revisions.
7. Add one authoritative timestamp source for stale-peer tests.
8. Avoid wall-clock sleeps in unit tests; inject clocks where possible.
9. Make browser waits poll semantic datasets instead of arbitrary timeouts.
10. Record connection failure reason without leaking secrets or raw tokens.
11. Distinguish local-tab, WebSocket, and offline-local transport in UI.
12. Verify BroadcastChannel names include world ID and protocol version.
13. Verify WebSocket messages include protocol version and sequence.
14. Test duplicate join and duplicate action idempotency in browsers, not only server units.
15. Test abrupt page close, not only graceful leave.
16. Test three clients to expose pairwise assumptions.
17. Test a late join after an enemy has died and a corpse exists.
18. Test two simultaneous corpse claims.
19. Test reconnect during quest phase transition.
20. Test reward retry after acknowledgement loss.
21. Keep personal inventory unavailable to remote peers.
22. Ensure remote transforms never control local collision or camera.
23. Add bounded interpolation buffers and stale snapshot rejection.
24. Add interest-management hooks before player counts grow.
25. Ensure model clones share immutable geometry/materials where safe.
26. Measure detached DOM nodes and GPU objects after repeated join/leave.
27. Add feature-load cancellation on page destroy.
28. Make optional API explorer and diagnostics imports user-triggered.
29. Preserve accessibility labels and keyboard reachability in connection UI.
30. Require a final plan-versus-actual audit, full readback, exact tests, live browser evidence, and durable handoff before stopping.

## Third-phase revelation

The next safe implementation is not the whole roadmap at once. It is a fully proven default multiplayer foundation that leaves explicit, tested seams for authority, loading, quests, UX, and scale. Once that foundation is live and measured, the subsequent nodes can be executed without guessing.
