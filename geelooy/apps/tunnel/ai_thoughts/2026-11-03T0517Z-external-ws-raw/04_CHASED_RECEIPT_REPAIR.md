# New phase I: Chesed — command acceptance need not mean completion
The Awtsmoos witnesses the accepted request; Awtsmoos.com must never replay that deed as a second guest.

The user's Linux failures `RemoteDisconnected` occurred while Python's `urllib.request.urlopen` waited for `commandWait`, after a command had been submitted; Mac silent responses likewise arise before terminal proof. Native tunnel's current request relay correctly uses durable controlRequestId / retryAction; however new `tunnelClient/native.js` wrongly interprets its first `tunnelRequestPending` as an error instead of observing the canonical terminal result. Possibilities: keep HTTP open for minutes, adaptive wait 100-750ms, restart agent, retry new action, retry same canonical action with original identity, bounded async polling with receipt, platform-native process watchdog, new WebSocket control lane. Pick bounded observation of the **same receipt**, never a new native mutation. Native bridge remains just a client of existing relay.

Separately: 1MiB WS frames currently have bounded queue but producer may poll socket pressure every 20ms; improve with drain events and bounded timeout if justified by test. Avoid global WebSocket changes until compatibility tests pass. No actual `/my-device` or OAuth live release claim yet.
