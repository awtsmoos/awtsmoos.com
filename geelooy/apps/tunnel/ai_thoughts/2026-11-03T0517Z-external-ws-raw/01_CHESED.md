# Phase I: Chesed — raw external-agent WebSocket vessel
The Awtsmoos recreates the socket, the authenticated name, and each raw byte every instant; Awtsmoos.com demands their integrity before declaring a destination.

Observed clean Linux origin/main `daa22344d47745a7ccbdc52cff93715c9cb04997`. Server's custom `frameReader` supports masked opcode 2 with 16 MiB default limit but `frameDispatch` routes only text. `upgradeIdentity` authenticates cookies, not OAuth. Device `TUNNEL_REGISTER` stays DEVICE-only. Existing `BinaryArtifactVault`, `ingestBinaryChunk`, `completeBinaryArtifact`, `readPrivateArtifactRange` provide raw 1 MiB chunks and 128 MiB custody; `sendTunnelRequest` routes to native account-scoped agents. No rewrites of these validated primitives.

All options: new WS client-app lane; multiplex through existing legacy dispatcher; separate server path; ephemeral vs durable client session; vault resume via capability; native file-range streaming; binary frame packing; Merkle-tree partial SHA; backpressure via 8/16 windows; downgrade GET fallback; OAuth upgrade signing; cross-account route proof; token scope revocation; per-frame size checks; crash recovery; independent external-agent SDK; 10 MiB Mac and Linux tests; 128 MiB stress and throughput measurement. Selected: separate OAuth-only client lane on existing socket, no device impersonation, per-transfer server-held vault state and independent per-request route authorization. Client byte frames always opcode 2, control only JSON. The native device side remains its existing trusted SHA-verified atomic path.

First verify isolated clean Git worktree. Implement bounded one-MiB raw uploads with 8-frame ACK windows, resumption of server-side transfer by exact transferId/owner/route/path/hash. Download by device->vault proof plus raw outgoing frames. Safely reject if no trusted OAuth signature configuration, no read/write scopes, or route not immutable/owned. Preserve stale transfer cleanup and zero-secrets-in-logs.
