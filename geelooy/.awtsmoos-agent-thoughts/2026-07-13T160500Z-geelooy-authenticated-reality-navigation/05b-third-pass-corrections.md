## Third-Pass Corrections

The first plan risked treating a strong clue as a finished diagnosis. The final correction is to separate three URL universes:

- Production/application semantics.
- Port `8080`, whose public root is already `geelooy`.
- Port `4173`, whose public root is the repository.

A URL valid on one origin can be invalid on another without any source defect. Therefore:

1. The actual emitted route markup is the primary evidence.
2. A module request returning JSON with HTTP 200 is a failure even when status checks alone pass.
3. The test matrix must pair each origin with its correct public prefix.
4. No source path should be changed merely to make both origins accept the same incorrect URL.
5. Hybrid-navigation expansion is not part of the correction unless lifecycle proof exists.
6. Authentication mutations remain a separate gated phase.
7. Concurrency requires fresh Git status immediately before and after every write.
8. Browser evidence is invalid without a private target ID and URL check.
9. Service-worker clearing is prohibited until ownership and scope are known.
10. A documentation-only result is legitimate when runtime source is correct.
