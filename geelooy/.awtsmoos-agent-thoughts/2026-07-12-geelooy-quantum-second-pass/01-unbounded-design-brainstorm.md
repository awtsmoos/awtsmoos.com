# B"H — Phase One: Unbounded Design Brainstorm

## Central idea
Geelooy should feel less like a collection of cards and more like a navigable field of living signals. The interface can be visually extreme without becoming confusing when every effect is attached to a real concept: identity, route, search, creation, incoming signal, outgoing signal, world, post, or conversation.

## Home possibilities
- Turn the above-fold area into a single spatial composition rather than a hero plus several unrelated cards.
- Treat the floating header as a hovering instrument with three visible depths: route identity, search lens, and identity/mail/navigation satellites.
- Let the orbital Aleph become a real structural anchor for search, route transitions, and creation entry points.
- Make the real feed read as a river of transmissions with alternating spatial offsets, shared vertical energy spine, and clear post metadata.
- Replace repeated equal-weight rectangles with blades, capsules, cut-corner panels, circles, arcs, and asymmetric negative space.
- Keep native links beneath every spectacular control.
- Attach color to system meaning: cyan navigation/search/incoming, violet spatial structure, magenta rare energy peaks, emerald live/synced/success, gold Mail outgoing/decisive actions.
- Surface real Heichel, alias, Mail, Torah, creation, and app destinations through one coherent network map.
- Build a useful quiet state when the real feed is empty, without fictional posts.
- Use typography scale and spacing before adding more effects.

## Header possibilities
- Make the B"H jewel the stable origin point.
- Display current route as a small luminous coordinate rather than a conventional breadcrumb.
- Let the search lens visibly expand from the header artifact into a portal.
- Use the Mail portal as a direct gold/cyan frequency gate with unread count only when real data exists.
- Give the profile control a visible alias glyph and state ring backed by real dropdown logic.
- Open the route constellation into an orbital geometry that still exposes normal anchors and keyboard order.
- Compress the mobile header into a deliberate five-control instrument rather than a shrunken desktop layout.

## Search possibilities
- Separate route, space, Torah, post, and identity results by semantic bands.
- Keep query-aware native Torah and route links even if live search fails.
- Show loading as a focused pulse, not a blocking animation.
- Preserve recent local searches without pretending they are server history.
- Add keyboard row movement, active descendant semantics, Escape, outside click, and full-screen mobile mode.
- Make the visual core react subtly to query length and result category.

## Quantum Mail possibilities
- Treat sender list and active thread as two synchronized instruments rather than ordinary panes.
- Make folder navigation a compact frequency rail with clear labels and counts.
- Show current alias as the transmission identity at the top of the sender deck.
- Give every conversation row a strong sender/subject/snippet/time hierarchy.
- Make empty Mail compelling through truthful orientation, compose, alias switching, Profile, and folder education.
- Differentiate incoming cyan and outgoing gold through alignment, edge light, avatar/glyph, and metadata—not only background color.
- Make the composer feel like opening a transmission chamber while remaining a native labeled form.
- Keep long text, links, code blocks, and replies highly readable.
- Give error and retry states their own obvious system language.
- Make mobile sender/thread navigation a deliberate sliding mode with visible back affordance.

## Other route possibilities
- Spaces can feel like world discovery using real Heichel data and ownership state.
- Profile can become an identity console centered on account, aliases, default alias, owned worlds, and real activity.
- Notifications can become a signal center with semantic grouping and read state.
- Apps can become studios/tools grouped by actual destination and capability.
- About can use the same spatial grammar to explain Awtsmoos and Geelooy without becoming a generic startup page.

## Accessibility and performance possibilities
- Use pseudo-elements and small SVG geometry instead of canvas outside Mail.
- Keep transform/opacity animations short and interruptible.
- Disable nonessential motion under reduced motion.
- Preserve visible focus on every control.
- Keep contrast readable in normal and forced-color modes.
- Never delay navigation for animation.
- Prevent fixed controls from covering content.
- Avoid page-wide blur/filter animation.

## Noncommitment rule
This brainstorm names possibilities, not approved edits. Actual files will be selected only after current DOM, current imports, Git history, APIs, and tests reveal which options fit the real architecture.
