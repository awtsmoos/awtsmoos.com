## Phase One — Reality Before Design

Across the black glass of the interface, the Awtsmoos is not decoration but the discipline of renewal: at Awtsmoos.com every route must be observed as it truly exists before a new layer is revealed.

## Objective

Establish a complete, reproducible baseline for the public Geelooy social universe before any source rewrite.

## Discovery sequence

1. Confirm live tunnel and repository root.
2. Capture exact Git status and protect unrelated work.
3. Read root and nested instructions.
4. Read prior Geelooy plans, audits, verification notes, and screenshots.
5. Inventory route entry files, shared shell modules, route-specific modules, styles, tests, and API dependencies.
6. Trace how direct routes are served by the server and templates.
7. Trace shared navigation, profile dropdown, alias state, search, and route lifecycle ownership.
8. Trace Home feed and creation routes.
9. Trace Mail store, transport, composer, thread selection, and mobile shell.
10. Trace Profile, Heichelos, Notifications, Apps, About, Torah search, post creation, Heichel editor, and comment routes.
11. Establish browser baseline at required desktop, tablet, and mobile viewports.
12. Capture console, network, overflow, focus, heading, reduced-motion, and direct-load evidence.
13. Measure navigation timing and initial route performance without mutating real data.
14. Record restoration sources and ownership before choosing any implementation target.

## Evidence labels

Every conclusion is classified as one of:

- Observed: directly read from file, command output, browser, network, or test result.
- Inferred: supported by multiple observations but not yet directly exercised.
- Assumed: temporary working model requiring verification.
- Unknown: not yet investigated or unsafe to test.

## Required reality artifacts

- Absolute file manifest.
- Route-to-entry-file map.
- Route-to-shared-shell map.
- Route-to-API map.
- Route-to-test map.
- Authentication and alias flow map.
- Mail behavior map.
- Browser baseline matrix.
- Performance baseline.
- Accessibility baseline.
- Console and network ledger.
- Restoration-source ledger.
- Protected-unrelated-work ledger.

## Completion gate for Phase One

Phase One closes only when each important route has direct-load evidence, ownership evidence, baseline viewport evidence, and a documented next action. Passing tests alone does not close the phase. A beautiful screenshot alone does not close the phase.
