# Planned Versus Actual

The Awtsmoos reveals a project through evidence rather than the flattering memory of a plan. This record compares the requested universe with the work actually completed in the living Awtsmoos.com repository.

## Planned

- Discover every HTML entry point and its transitive stylesheet graph.
- Find broken imports, duplicate visual generations, dynamic style injection, responsive conflicts, and service-worker risks.
- Establish coherent shared ownership without creating a parallel theme.
- Repair Home, global navigation, discovery, Ikar, Mail, Composer, media and secondary routes.
- Verify representative desktop and mobile routes in real Chrome.
- Prove contrast, touch targets, overflow, naming, reduced motion, syntax, route contracts, and cache freshness.
- Preserve unrelated work and create no commit.

## Actual source discovery

- Inventoried 201 HTML entry points.
- Traversed more than 950 unique live stylesheet files through direct links and transitive imports.
- Found five broken stylesheet destinations and repaired all five.
- Identified 59 scripts capable of injecting style nodes or stylesheet links.
- Captured the initial browser matrix for 28 major route families at 390 × 844 and 1440 × 1000.
- Captured the full Home viewport matrix at 320, 360, 390, 412, landscape, tablet, and desktop widths.

## Actual implementation

- Rewrote 23 production files and created focused modules where ownership was previously oversized or ambiguous.
- Restored root compatibility styles without imposing a second product theme.
- Repaired Home focus, contrast, feed actions, touch dimensions, loading states, and reduced motion.
- Repaired the shared mobile header, search portal, duplicate navigation, and inherited centering transform.
- Repaired Heichel discovery metadata contrast and touch dimensions.
- Split final Ikar controls into field and navigation modules scoped to the real live body class.
- Repaired Mail mobile containment and touch targets.
- Added stable and dynamic accessible names to the Social Composer and repaired editor control sizes.
- Replaced repeated origin-wide cache cleanup with a versioned one-time retirement contract.

## Actual verification

- Final Home: no horizontal overflow and no visible-text AA failures in the persisted 390 × 844 receipt.
- Final Ikar at 390 × 844: document width 375, no unnamed controls, no actionable target below 44 pixels, header contained from 5.6 to 369.4 pixels, transform `none`.
- Final Mail at 390 × 844: document width 390, no unnamed controls, no actionable target below 44 pixels; hidden chat pane contained inside the viewport with no pointer input.
- Final Composer at 390 × 844: document width 375, no unnamed controls, no actionable target below 44 pixels.
- Focused CSS quality, imported-style ownership, route coverage, and Heichel quality tests passed.
- Every touched production file is at most 120 lines, uses tabs for indentation, and carries the required blessing header.

## Deliberate boundaries

- No authenticated or destructive action was submitted.
- Existing dynamic route contracts were preserved rather than migrated.
- Historical Heichel visual generations remain imported where removal would require a separate reader regression project; final control ownership now wins explicitly.
- The 670-line legacy modal builder and other dynamic style monoliths were identified but not partially patched because they require complete modular rewrites and dialog regression tests.
- Many unrelated files changed concurrently in the worktree. They were neither reset nor modified as part of this pass.
- No commit was created.
