# Second Critique — Thirty Further Improvements

1. Reuse existing mobile toggles before adding markup.
2. Reuse current panel IDs and ARIA relationships.
3. Avoid duplicate desktop and mobile headers.
4. Make the app bar adaptive.
5. Prefer grid areas over nth-child positioning.
6. Use 100dvh with fallback.
7. Use visualViewport only if CSS cannot solve keyboard overlap.
8. Preserve static usability before JavaScript initializes.
9. Avoid body transforms that break fixed descendants.
10. Keep drawers inside the app root.
11. Use logical properties.
12. Keep scrollbars readable.
13. Support long conversation titles.
14. Keep mobile form controls at 16px or larger.
15. Add min-width:0 to vulnerable flex/grid children.
16. Use overflow-wrap only where needed.
17. Preserve horizontal scrolling for code.
18. Make role-aware message widths balanced.
19. Distinguish user messages with contrast, not muddy gradients.
20. Give tool and status records a compact visual language.
21. Keep stream indicators width-stable.
22. Let composer controls wrap at large text sizes.
23. Test 320px and 200% zoom.
24. Do not hide useful scrollbars.
25. Make collapsible sections stateful and clear.
26. Keep automation labels visible.
27. Use helper text only where it reduces confusion.
28. Verify practical color contrast.
29. Add drawer geometry and scroll-owner tests.
30. Make the three-squeezed-column mobile failure impossible.

## Final posture

Inspect first, select the smallest structural architecture that creates a coherent responsive workspace, rewrite complete focused files, and verify at real viewport sizes.
