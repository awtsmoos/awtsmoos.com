# Phase One: Unbounded Discovery Brainstorm

## Goal

Make `https://awtsmoos.com/ai/relay/install/awtsmoos-server-extension.zip` a canonical, deterministic, directly downloadable browser-extension artifact, and make the complete installation order understandable and verifiable.

## Possible root causes

- The ZIP filename is referenced by UI or documentation but never committed or built.
- The server treats `/ai/relay/install/*` as dynamic application routes rather than static files.
- Static serving excludes `.zip` files or the `install` directory.
- The extension source lives elsewhere under `relay/split-browser` and no packaging step copies it.
- The archive exists locally but is ignored by Git or deployment tooling.
- The public URL is stale and should point to a different canonical artifact.
- A security allowlist blocks binary files while scripts remain reachable.
- The archive is generated by a script that is not run in deployment order.
- A route precedence issue sends the request to a dynamic catch-all before static lookup.
- The archive root layout may be invalid even after the route is made reachable.

## Candidate solution families

1. Commit a deterministic ZIP artifact beside the installers.
2. Add a build script that recreates the ZIP from canonical extension source.
3. Add an explicit binary download route with safe path containment.
4. Correct a stale link to an already served artifact.
5. Serve the extension folder through a release endpoint that packages on demand.
6. Add a deployment hook that rebuilds the archive before server startup.
7. Add route tests that assert headers, size, ZIP magic bytes, and archive integrity.
8. Add installation documentation ordering server, extension, relay, and browser setup.

## Architecture graph

```text
Extension source
	-> deterministic packager
		-> awtsmoos-server-extension.zip
			-> static server or explicit route
				-> public download URL
					-> install UI/documentation
						-> browser extension installation
```

## Evidence required before implementation

- Exact extension source directory and manifest.
- Every reference to the target filename and URL.
- Server route/static-file behavior for `.zip`.
- Deployment/build scripts and ignore rules.
- Current Git status and neighboring conventions.
- Existing route tests or HTTP smoke-test patterns.

## First-pass file universe

Potentially touched files include the canonical extension source, packaging script, package metadata, installer documentation/UI, server static or route configuration, focused tests, and the generated ZIP artifact. No production file will be modified until each is read fully and the route is traced end to end.
